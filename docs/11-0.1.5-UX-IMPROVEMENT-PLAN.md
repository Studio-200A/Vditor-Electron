# Version 0.1.5 - UX Improvement Plan

## 0.1.3版本存在问题 - 需在0.1.5版本关闭

### 交互与UI

- 侧边栏拖拽宽度动画延迟：当没有标签页打开，或 Vditor 工具栏隐藏时，拖拽侧边栏（sidebar）右边缘调整宽度，`div.toolbar-sidebar-tabs.sidebar-tabs` 的宽度跟随动画存在延迟；当工具栏显示且有标签页打开时无此现象。
- 查找与替换滚动动画：在查找框输入文字并按下回车后，匹配项定位导致的页面位置跳变比较生硬，希望增加平滑滚动动画。
- 大纲跳转抖动：点击两个相近章节的大纲标题时，目标位置很近，页面本不应滚动，但当前会出现类似滚动的抖动；需要在此场景下规避该抖动。
- titlebar投影：当前 `<vditor-toolbar>`有下方投影效果，但是在菜单-布局选项中关闭这个工具栏后，`<vditor-toolbar>`上方的titlebar未在下方投影，需补上。
- 底部状态栏：显示当前所处编辑区域模式的位置 `<span#statusMode>`需要做成可点击样式（包含鼠标指针hover高亮效果），点击后在上方展开小型选项菜单，包含三个选项：`WYSIWYG` 、`IR`和 `SV`，并在当前已生效模式前方加 `✔`（注意未选中模式文字前也要预留 `✔`空间，保证排版对齐），点击后关闭菜单切换编辑模式，点击其他区域不改变编辑模式并收回菜单。此处不做本地化，用极简方式实现另一个快速切换编辑模式的渠道。功能非常简单直观，用户简单尝试实践即可掌握用法。注意菜单外观匹配三种app主题，参考顶部titlebar `Vditor Desktop`菜单。
- Sidebar开关按钮：点按 `button#toggleSidebar-titlebar-sidebar-toggle`开启/关闭sidebar同步控制新建、打开、保存三个按钮显隐时，`button#toggleSidebar-titlebar-sidebar-toggle`元素仍会发生少量横向位移。理想情况下该元素应保持不动。
- 文档当前位置与编辑模式：切换编辑模式会出现文档显示位置重置回顶部，或移动到当前位置附近的情况；理想状态下切换编辑模式不应该变文档当前显示位置，SV编辑模式以代码编辑区对应位置为准。

### 设置相关

- 编辑模式保存错误：软件保存的是关闭前的编辑模式，而非设置页配置的默认编辑模式。复现步骤：将设置中的默认编辑模式设为“即时渲染”→ 通过 Vditor 工具栏切换到分栏模式 → 关闭并重新打开软件 → 软件仍处于分栏编辑模式。
- 设置页面 - 编辑器 - 编辑器布局 - 文字段落宽度范围：当滑动条设置为100%时，整体编辑区域偏左，且在所见即所得模式下，和即时渲染模式下，`h1#ir-Vditor-Desktop_0.vditor-ir_node::before`同类型元素处于窗口之外不可见区域。
- 设置页面中的下拉菜单，在点选选项后，`<select>`元素会被高亮色包围，但当前这个高亮色在三个app主题下不匹配对应主题高亮色，需修改为对应高亮色。
- 设置页面在Monokai Pro Dark主题下，`checkbox`和 `range-control`未使用该主题高亮色/重点色，而是错误沿用了Dark主题的颜色。
- 设置页面 - 关于 - Chrome DevTools开关：在设置 - 关于页面增加Chrom DevTools开关，将 `button#resetSettings.danger`元素上移，为其在下方腾出Chrom DevTools开关位置。开关左边文案为 `Chrome DevTools`，不进行本地化，开关本体形式为滑块，参考状态栏 `status.toggleTheme`元素样式。此开关不更改默认快捷键，关闭时快捷键不应打开DevTools。本增设开关行为不改变打开Chrome DevTools的快捷键，开关文案不提示快捷键。
- 设置页面：`modal card settings-card`在开启状态下应响应按下 `Escape`键关闭。

### 链接跳转

现状（按三种编辑模式对比）：


| 链接类型                             | 所见即所得 | 即时渲染 | 分栏（预览区）                            |
| ------------------------------------ | ---------- | -------- | ----------------------------------------- |
| 目录（TOC）链接                      | 无法跳转   | 可以跳转 | 点击TOC链接，链接文字变红，但无法进行跳转 |
| 网络链接                             | 可以跳转   | 可以跳转 | 可以跳转                                  |
| 指向本地 Markdown 文档的相对路径链接 | 无法跳转   | 无法跳转 | 无法跳转                                  |

需要统一三种编辑模式下的链接跳转机制（机制待讨论）：

- 三种模式都应支持目录（TOC）链接点击跳转；分栏模式指预览区内的链接点击。
- 三种模式当前都支持网络链接点击跳转，符合预期；分栏模式指预览区内的链接点击。
- 三种模式都应支持指向本地 Markdown 文档的相对路径链接跳转，点击后在新标签页打开目标文件；仅支持 Markdown 文档，指向其他格式文档不响应点击（符合 Markdown 编辑器定位）。
- 三种模式应有统一的点击跳转交互逻辑：直接点击将光标移动到文字处供编辑，并弹出 tooltip 提示按下 Ctrl+点击进行跳转。

开发前待确认：上述逻辑的落地位置，写在 `app.js` 还是 `vditor-adapter.js`。

### Vditor原生编辑区

#### 大纲

- Vditor在所见即所得模式和即时渲染模式下，自带工具栏有大纲按钮，点击可打开其内置大纲功能，功能上与Vditor Desktop重复。需考虑二选一决策：

  - 彻底屏蔽Vditor内置大纲功能；
  - Vditor大纲功能替换至Vditor Desktop大纲功能，使其在三种编辑模式下均可用；
  - 注：逐步测试发现vditor大纲页面外在特征：
    - 点击大纲标题文档页面跳转没有滚动动画；
    - 点击大纲 `>`展开按钮，变成 `v`时有转向动画，类似当前搜索框点击 `button#findToggleReplace.find-toggle`元素的动画；
    - vditor自带大纲宽度不可调整；

#### 编辑区留空区域

- UI改进：当前三种编辑模式下，编辑区域底部紧贴状态栏和窗口底沿，体验不佳；需要在编辑区域底部增加当前窗口高度半屏左右留空区域，增强文档底部区域编写体验；需要决策是采用固定高度留空区域，还是根据当前窗口高度动态设置为其50%高度；（参考思源笔记实现方式，目测是动态调整）

## 0.1.5版本主要体验优化

### 编辑区右键菜单与两段式全选

#### 设计目标

Vditor 作为浏览器编辑器时可使用浏览器原生右键菜单；Vditor Desktop 应在真实编辑区提供统一的应用级右键菜单，补齐桌面编辑器的高频操作体验。该菜单不修改 Vditor vendored 源码，不扩展顶部 Vditor 工具栏，也不依赖已缓期的浮动工具栏。

应用已有全局 `#contextMenu` 容器及文件树右键菜单。后续应将其收束为通用菜单能力，避免文件树与编辑区分别控制同一个菜单 DOM。

#### 通用编辑菜单

以下项目在 WYSIWYG、IR、SV 三种编辑模式的真实可编辑区域内均可用：

```text
撤销                  Ctrl/Cmd+Z
重做                  Ctrl/Cmd+Shift+Z
────────────────────
剪切                  Ctrl/Cmd+X
复制                  Ctrl/Cmd+C
粘贴                  Ctrl/Cmd+V
粘贴为纯文本
删除
选择当前块            Ctrl/Cmd+A（首次）
```

要求：

- 右键仅拦截当前活动标签页的可编辑区域；SV 右侧预览区、只读预览节点、设置页、查找输入框和文件树仍保留各自语义或原生行为。
- 菜单打开前保存当前 Range；菜单按钮在 `mousedown` 阶段阻止默认失焦；执行命令前恢复该 Range，避免右键或点击菜单导致操作目标丢失。
- `Escape`、点击外部、切换标签页或编辑模式、编辑器重建、标签关闭时必须关闭菜单并释放保存的 Range。
- 菜单位置需夹紧在窗口可视边界内；不可留下透明但可点击的区域。
- 剪切、复制、删除、撤销、重做和粘贴优先复用 Vditor 的既有事件与 undo 栈；不得通过 `getValue()` -> 字符串修改 -> `setValue()` 破坏光标和撤销历史。
- 粘贴为纯文本需要先验证 Chromium `document.execCommand` 是否可保持 Vditor 三模式行为；若不能满足要求，再经 preload 增加最小化的剪贴板读取能力，不暴露通用 `ipcRenderer`。
- 所有菜单文案、tooltip、禁用状态说明均通过 `src/renderer/locales.js` 提供 `en_US`、`zh_Hans`、`zh_Hant` 三种语言。

#### 表格专属菜单

表格操作只在 WYSIWYG 与 IR 模式中，且右键落在当前表格的真实 `td` 或 `th` 单元格内时显示：（此处新增行和新增列选项文本内容暂不增加方向信息，从文本上更符合一眼可判断的特征；用户可以很快通过实践发现新增行列方向，掌握用法）

```text
────────────────────
新增行
删除当前行
新增列
删除当前列
```

范围与取舍：

- 首版只支持向下新增行、向右新增列，不提供反方向操作、批量选择、合并/拆分单元格或复杂表格编辑器。
- SV 是 Markdown 源码编辑区，表格应直接通过编辑 Markdown 文本修改；SV 不显示上述四项。
- 删除唯一一列导致整张表被删除等行为必须与 Vditor 3.11.3 的既有语义一致，并在实现前验证。
- WYSIWYG 与 IR 均应保留 Vditor 的内容同步、Markdown 序列化、光标恢复和 undo 行为。

Vditor 3.11.3 内部已有 WYSIWYG/IR 共用的 `insertRow`、`deleteRow`、`insertColumn`、`deleteColumn` 路径，但没有公开的表格 API。实现必须遵守：

- 所有表格上下文识别、私有 DOM selector、Range 恢复和表格动作适配均集中在 `src/renderer/vditor-adapter.js`。
- adapter 对外仅暴露语义化接口，例如 `tableContext()` 与 `performTableAction()`；`app.js` 不得直接查询 Vditor 表格 DOM 或复制 Vditor 内部实现。
- 不得通过伪造快捷键调用内部表格操作，也不得以 Markdown 全量重写方式修改 WYSIWYG/IR 表格。
- adapter 中相关代码需注明：该实现依赖 Vditor 非公开 DOM/内部行为，不属于稳定公开 API；升级 Vditor 时必须复核表格上下文、四个动作、Markdown 输出、光标和撤销契约。

#### 菜单外观匹配主题

- 注意菜单外观匹配三种app主题，参考顶部titlebar `Vditor Desktop`菜单。

#### 两段式 Ctrl/Cmd+A

在焦点位于当前活动 Vditor 的真实可编辑区域时，覆盖浏览器默认全选，采用“上下文选择 -> 当前编辑器全文选择”的两段式逻辑：


| 当前上下文                    | 第一次 Ctrl/Cmd+A               | 第二次 Ctrl/Cmd+A      |
| ----------------------------- | ------------------------------- | ---------------------- |
| WYSIWYG 普通内容              | 选择当前可编辑 block            | 选择当前编辑器全部内容 |
| IR 普通内容                   | 选择当前 `data-block="0"` block | 选择当前编辑器全部内容 |
| WYSIWYG / IR 的非空表格单元格 | 选择当前 `td/th` 单元格内容     | 选择当前编辑器全部内容 |
| WYSIWYG / IR 的空表格单元格   | 直接选择当前编辑器全部内容      | 保持全文选择           |
| SV                            | 选择当前逻辑源码行              | 选择当前源码全文       |

“选择当前块”是本项目对 Vditor 编辑 DOM 的上下文选择，不引入思源笔记式 block 文档模型、块级批量操作状态或持久 block ID。表格内菜单和快捷键均以“当前单元格内容”为首层选择单位。

算法不使用“连续按键时间窗口”或独立计数器，而是根据浏览器当前 Selection 是否完整覆盖当前上下文决定升级范围：

```text
若当前 Selection 未完整覆盖当前 block / 单元格 / 源码行：
  选择该上下文
否则：
  选择当前模式的完整可编辑内容
```

这与思源笔记的 `selectAll()` 判定模型一致：空单元格文本长度为零，选择范围天然已经覆盖其全部可见内容，因此第一次按键直接升级为全文选择。该行为避免了不可见、没有反馈的空单元格“已选中”状态。

实现要求：

- 在 `vditor-adapter.js` 集中提供上下文识别、完整选择判断、选择上下文和选择全文的窄接口；WYSIWYG/IR 的 block 与 cell DOM 契约不得泄漏到 `app.js`。
- 仅在 Vditor 编辑器拥有焦点时拦截 `Ctrl/Cmd+A`；查找框、设置输入框、文件树重命名输入框及其他非编辑器控件保留系统默认全选。
- selection 被用户鼠标操作、方向键移动、输入、粘贴、剪切、撤销/重做、切换标签页或模式、失焦、关闭菜单/编辑器后，下一次快捷键应自然从上下文选择重新开始。
- 程序主动设置第一次 Selection 时，不能把自身触发的 `selectionchange` 误判为用户修改而立即升级或重置状态。
- 右键菜单中的“选择当前块”和快捷键首次行为必须调用同一个 adapter API，防止两条路径语义漂移。

#### 验收与测试

- WYSIWYG、IR、SV 三种模式下验证通用右键菜单的可见性、禁用状态、菜单定位、失焦关闭与 Range 恢复。
- 验证通用编辑命令不破坏 Vditor 内容、光标、修改状态和 undo/redo 历史。
- WYSIWYG 与 IR 中分别验证表格四项操作、仅在单元格内显示、Markdown 输出、撤销恢复、删除边界和切换模式后的结果。
- SV 中验证表格菜单不显示，通用菜单仍可用。
- 三种模式分别验证 Ctrl/Cmd+A 的“上下文 -> 全文”升级；验证空单元格首次即全文、非空单元格首次选内容。
- 验证在查找框、设置输入框等非编辑器控件按 Ctrl/Cmd+A 仍执行原生全文本选择。
- 为 adapter 的 Vditor 私有 DOM 契约增加聚焦单元测试；在真实 Electron/Vditor E2E 中覆盖右键、表格和快捷键路径。
