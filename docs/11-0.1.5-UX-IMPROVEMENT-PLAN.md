### ✅ 链接跳转

#### 设计目标

Vditor-Electron 保留 Markdown 编辑器的直接编辑属性，同时为链接提供明确、可预测的跳转方式：普通单击用于编辑，按下平台对应的导航修饰键再单击才执行跳转。方案适用于 WYSIWYG、Instant Rendering（IR）和 Split View（SV）三种编辑模式，并覆盖文内锚点、TOC、外部 URL 与相对 Markdown 文件链接。

#### 交互规范

| 场景                                                  | 普通单击                         | Ctrl（macOS 为 Cmd）+单击                        |
| ----------------------------------------------------- | -------------------------------- | ------------------------------------------------ |
| WYSIWYG / IR 内链接                                   | 光标定位到链接文本，显示 tooltip | 执行跳转                                         |
| SV 预览区链接                                         | 显示 tooltip，不打开链接         | 执行跳转                                         |
| `#锚点`、TOC                                          | 显示 tooltip，不跳转             | 当前标签平滑滚动至目标标题                       |
| `http(s)` / `mailto:`                                 | 显示 tooltip，不跳转             | 通过主进程交给系统默认应用                       |
| 相对 Markdown 文件                                    | 显示 tooltip，不跳转             | 新标签打开目标文件；若含 `#锚点`，打开后继续定位 |
| 非 Markdown 本地文件、绝对文件路径、`file:`、未知协议 | 不响应跳转                       | 不响应跳转                                       |

普通点击用于编辑、而 Ctrl/Cmd+点击可跳转的链接，必须显示对应平台操作提示：Windows/Linux 使用 `Ctrl+Click`，macOS 使用 `Cmd+Click`。提示文案纳入 `en_US`、`zh_Hans`、`zh_Hant` 三语本地化。

普通悬停使用文本编辑光标；按住 Ctrl/Cmd 悬停在可跳转链接文字上时切换为手形光标；松开修饰键或移出链接后恢复原始指针。SV 预览区没有可编辑光标，普通单击只显示 tooltip，不尝试猜测源码位置。

#### 链接范围与安全边界

相对 Markdown 链接支持 `.md`、`.markdown`、`.mdown`、`.mkd`、`.mkdn`，允许 `../`，但未保存文档不解析相对链接。主进程拒绝协议、绝对路径、非 Markdown 扩展名、非法百分号编码和不存在的目标。

外部 URL 仅允许 `http:`、`https:`、`mailto:`；`file:`、`javascript:`、`data:`、`app:` 及其他协议均不得交给系统处理。IPC、页面导航和新窗口请求共用同一协议白名单。

#### 架构职责

- `src/renderer/vditor-adapter.js` 集中维护 Vditor 私有 DOM 选择器和结构假设，提供链接/TOC 目标提取、编辑光标定位和 IR 链接展开等语义 API。
- `src/renderer/app.js` 处理修饰键、tooltip、鼠标指针、当前标签滚动、打开新标签和错误提示，并保留标签及会话状态所有权。
- `src/main/resolve-markdown-link.ts` 解析并校验相对 Markdown 链接；`src/main/external-url.ts` 提供外部 URL 白名单校验。
- `src/main/index.ts` / `src/main/preload.ts` 通过窄 IPC 和 context bridge 暴露必要能力，渲染进程不直接访问文件系统或 Electron `shell` API。

#### 实现与验证记录

已完成文内锚点/TOC、三模式链接交互、IR 链接编辑、相对 Markdown 文件跳转、相对图片资源解析和外部 URL 安全收口。相关单元测试与 Electron E2E 已覆盖这些路径；后续若继续修改，应在发布前重新执行完整验证。

### ✅ Vditor原生编辑区

#### 大纲

- **现象**：Vditor 在 WYSIWYG 和 IR 工具栏中提供原生大纲入口，与 Desktop 侧栏大纲重复；SV 中该入口由 Vditor 隐藏。原生大纲位于编辑器内部、宽度不可调整，点击标题直接改变滚动位置而没有平滑动画；其折叠动画和标题层级功能不能弥补三种编辑模式下入口与行为不一致的问题。

- **决策**：保留 Vditor Desktop 侧栏大纲，隐藏 Vditor 原生大纲功能。Desktop 大纲是应用级工作区能力，已与 Files 侧栏、主题、三语本地化、侧栏调宽和标签状态整合；它在 WYSIWYG、IR、SV 中都可用，并通过 adapter 在可见编辑/预览容器间执行平滑跳转。每个标签页独立维护大纲折叠状态，避免重绘或编辑模式切换后状态漂移。

- **实施记录**：已显式保持 `outline.enable: false`。Vditor 3.11.3 的模式切换仍依赖内部 `outline` 工具项，因此它作为无可见入口的内部占位项保留；adapter 以集中维护、带升级契约测试的方式隐藏该入口。旧的自定义 `toolbarItems` 若缺少该项，运行时补回内部占位项，不改写用户持久化设置。

- **标题解析实施记录**：Desktop 已通过 adapter 复用 Vditor 3.11.3 原生大纲的 content-element 选择规则：preview 可见时读取 preview 的直接 H1–H6，否则读取当前模式编辑区的直接 H1–H6。标题集合、折叠 key 与点击目标来自同一份原生 snapshot，不再叠加 Markdown 子解析器或按下标拼接另一份行号集合；点击目标直接保留对应标题 DOM 节点，不把标题序号误作直属子节点序号。SV 两侧标题数量一致时继续同步滚动；不一致时只滚动原生准则使用的 preview，且 preview 使用外层预览容器作为滚动目标，避免猜测错误节点或容器。Outline 视图隐藏时不再序列化文档或重建大纲。若要提供跨模式一致的 Setext/围栏 Markdown 语义，应作为独立功能决策。

#### 编辑区留空区域

- [x] UI改进：当前三种编辑模式下，编辑区域底部紧贴状态栏和窗口底沿，体验不佳；已采用随编辑器实际高度动态计算的 50% 留空区域，增强文档底部区域编写体验。

- **实施记录**：参考思源 `getPadding()` 的动态高度策略，通过 adapter 为 Vditor 3.11.3 的 SV、IR、WYSIWYG 和 preview 表面统一写入 `--editor-bottom`；Vditor 原有三种编辑模式的尾部 `::after` 生成可滚动留白，Desktop 为 preview 补足同等尾部元素。每个标签通过 `ResizeObserver` 在编辑器高度变化时更新，重建编辑器和关闭标签时断开 observer；不改变用户的打字机模式设置。

## 0.1.5版本主要体验优化

### ✅ 编辑区右键菜单

#### 设计目标

Vditor 作为浏览器编辑器时可使用浏览器原生右键菜单；Vditor Desktop 应在真实编辑区提供统一的应用级右键菜单，补齐桌面编辑器的高频操作体验。该菜单不修改 Vditor vendored 源码，不扩展顶部 Vditor 工具栏，也不依赖已缓期的浮动工具栏。

应用已有全局 `#contextMenu` 容器及文件树右键菜单。后续应将其收束为通用菜单能力，避免文件树与编辑区分别控制同一个菜单 DOM。

#### 通用编辑菜单

以下项目在 WYSIWYG、IR、SV 三种编辑模式的真实可编辑区域内均可用：

```text
剪切                  Ctrl/Cmd+X
复制                  Ctrl/Cmd+C
粘贴                  Ctrl/Cmd+V
粘贴为纯文本
删除
选择当前块            Ctrl/Cmd+A（首次）
```

要求：

- 右键仅拦截当前活动标签页的可编辑区域；SV 右侧预览区、只读预览节点、设置页、查找输入框和文件树仍保留各自语义或原生行为。
- 菜单打开前保存当前 Range；菜单按钮在 `mousedown` 阶段阻止默认失焦；执行命令前恢复该 Range，避免右键或点击菜单导致操作目标丢失。
- `Escape`、点击外部、切换标签页或编辑模式、编辑器重建、标签关闭时必须关闭菜单并释放保存的 Range。
- 菜单位置需夹紧在窗口可视边界内；不可留下透明但可点击的区域。
- 剪切、复制、删除和粘贴优先复用 Vditor 的既有事件；不得通过 `getValue()` -> 字符串修改 -> `setValue()` 破坏光标和撤销历史。
- 撤销和重做不列入右键菜单：沿用 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z 与 Vditor 顶部工具栏。Vditor 3.11.3 的私有 undo 快照存在已记录的上游限制，右键菜单不额外模拟快捷键或复刻历史栈。
- 粘贴为纯文本需要先验证 Chromium `document.execCommand` 是否可保持 Vditor 三模式行为；若不能满足要求，再经 preload 增加最小化的剪贴板读取能力，不暴露通用 `ipcRenderer`。
- 所有菜单文案、tooltip、禁用状态说明均通过 `src/renderer/locales.js` 提供 `en_US`、`zh_Hans`、`zh_Hant` 三种语言。

#### 表格专属菜单

表格操作只在 WYSIWYG 与 IR 模式中，且右键落在当前表格的真实 `td` 或 `th` 单元格内时显示：（此处新增行和新增列选项文本内容暂不增加方向信息，从文本上更符合一眼可判断的特征；用户可以很快通过实践发现新增行列方向，掌握用法）

```text
────────────────────
新增行
删除当前行
新增列
删除当前列
```

范围与取舍：

- 首版只支持向下新增行、向右新增列，不提供反方向操作、批量选择、合并/拆分单元格或复杂表格编辑器。
- SV 是 Markdown 源码编辑区，表格应直接通过编辑 Markdown 文本修改；SV 不显示上述四项。
- 删除唯一一列导致整张表被删除等行为必须与 Vditor 3.11.3 的既有语义一致，并在实现前验证。
- WYSIWYG 与 IR 均应保留 Vditor 的内容同步、Markdown 序列化、光标恢复和 undo 行为。

Vditor 3.11.3 内部已有 WYSIWYG/IR 共用的 `insertRow`、`deleteRow`、`insertColumn`、`deleteColumn` 路径，但没有公开的表格 API。实现必须遵守：

- 所有表格上下文识别、私有 DOM selector、Range 恢复和表格动作适配均集中在 `src/renderer/vditor-adapter.js`。
- adapter 对外仅暴露语义化接口，例如 `tableContext()` 与 `performTableAction()`；`app.js` 不得直接查询 Vditor 表格 DOM 或复制 Vditor 内部实现。
- 不得通过伪造快捷键调用内部表格操作，也不得以 Markdown 全量重写方式修改 WYSIWYG/IR 表格。
- adapter 中相关代码需注明：该实现依赖 Vditor 非公开 DOM/内部行为，不属于稳定公开 API；升级 Vditor 时必须复核表格上下文、四个动作、Markdown 输出、光标和撤销契约。

#### 菜单外观匹配主题

- 注意菜单外观匹配三种app主题，参考顶部titlebar `Vditor Desktop`菜单。

#### 实施与验证记录

已将文件树和编辑区收束到同一个 `#contextMenu` 菜单能力。编辑区仅在当前活动标签页的真实可编辑表面拦截右键；SV 预览、查找输入框及其他应用控件保持原有语义。打开菜单时 adapter 保存并在执行前恢复 Range，菜单项的 `pointerdown` / `mousedown` 不会夺走编辑器焦点；`Escape`、点击外部、切换标签页或编辑模式、重建和关闭标签都会关闭菜单并释放保存状态。撤销/重做菜单项经决策移除，继续使用通用快捷键和 Vditor 工具栏。

### ✅ 两段式 Ctrl/Cmd+A

在焦点位于当前活动 Vditor 的真实可编辑区域时，覆盖浏览器默认全选，采用“上下文选择 -> 当前编辑器全文选择”的两段式逻辑：

| 当前上下文                    | 第一次 Ctrl/Cmd+A               | 第二次 Ctrl/Cmd+A      |
| ----------------------------- | ------------------------------- | ---------------------- |
| WYSIWYG 普通内容              | 选择当前可编辑 block            | 选择当前编辑器全部内容 |
| IR 普通内容                   | 选择当前 `data-block="0"` block | 选择当前编辑器全部内容 |
| WYSIWYG / IR 的非空表格单元格 | 选择当前 `td/th` 单元格内容     | 选择当前编辑器全部内容 |
| WYSIWYG / IR 的空表格单元格   | 直接选择当前编辑器全部内容      | 保持全文选择           |
| SV                            | 选择当前逻辑源码行              | 选择当前源码全文       |

“选择当前块”是本项目对 Vditor 编辑 DOM 的上下文选择，不引入思源笔记式 block 文档模型、块级批量操作状态或持久 block ID。表格内菜单和快捷键均以“当前单元格内容”为首层选择单位。

算法不使用“连续按键时间窗口”或独立计数器，而是根据浏览器当前 Selection 是否完整覆盖当前上下文决定升级范围：

```text
若当前 Selection 未完整覆盖当前 block / 单元格 / 源码行：
  选择该上下文
否则：
  选择当前模式的完整可编辑内容
```

这与思源笔记的 `selectAll()` 判定模型一致：空单元格文本长度为零，选择范围天然已经覆盖其全部可见内容，因此第一次按键直接升级为全文选择。该行为避免了不可见、没有反馈的空单元格“已选中”状态。

实现要求：

- 在 `vditor-adapter.js` 集中提供上下文识别、完整选择判断、选择上下文和选择全文的窄接口；WYSIWYG/IR 的 block 与 cell DOM 契约不得泄漏到 `app.js`。
- 仅在 Vditor 编辑器拥有焦点时拦截 `Ctrl/Cmd+A`；查找框、设置输入框、文件树重命名输入框及其他非编辑器控件保留系统默认全选。
- selection 被用户鼠标操作、方向键移动、输入、粘贴、剪切、撤销/重做、切换标签页或模式、失焦、关闭菜单/编辑器后，下一次快捷键应自然从上下文选择重新开始。
- 程序主动设置第一次 Selection 时，不能把自身触发的 `selectionchange` 误判为用户修改而立即升级或重置状态。
- 右键菜单中的“选择当前块”和快捷键首次行为必须调用同一个 adapter API，防止两条路径语义漂移。
