# 0.2.5 版本资源健康专项

## 1. 专项目标

在批次 9 renderer composition 迁移完成并完成其收口验证后，为**当前已保存的 Markdown 文档**提供“工具 > 资源健康”入口。该入口在主窗口内打开与设置页同类的资源健康页面，帮助用户检查该文档最后一次成功保存版本与其本地图片资源之间的关系。

首版提供两类结果：

1. **未引用图片候选**：位于当前文档的图片目录、未被本次工作区扫描识别为引用的图片文件；
2. **缺失图片引用**：当前文档最后一次成功保存版本指向、但目标本地图片不存在的引用。

该功能服务于普通 Markdown 文件和普通目录，不引入专有文档格式、资源数据库、后台同步或隐式文件整理。它借鉴思源笔记“先展示资源关系、再由用户处理”的产品方向，但不复制其知识库、数据库、历史系统或全局 `assets/` 根模型。

## 2. 背景与问题

当前图片上传会在已保存文档所在目录下、按 `pasteImagesDir`（默认 `./assets`）写入图片，并插入相对 Markdown 链接。删除 Markdown 中的图片链接不会自动删除磁盘文件。

自动在保存、关闭、撤销、恢复或模式切换时删除资源不可接受：同一物理图片可能被同目录的其他 Markdown、HTML、工作区外文件或用户正在编辑但尚未保存的文档引用。当前上传文件名也不能证明资源只由 Desktop 创建或只属于某一份 Markdown。

MarkText 的位图粘贴可先生成 `data:` URL，再依赖后续图片动作决定是否落盘；这会让文档本身承载图片二进制。Desktop 保持现有的“文件落盘 + 相对 Markdown 链接”策略，不引入 Base64 图片作为资源清理的替代方案。

## 3. 设计原则

1. **先只读，后可恢复处理。** 扫描、预览与分类不修改文件；任何移除操作必须由用户显式选择、二次确认，并进入系统回收站。
2. **宁可漏报，不可误删。** 解析不确定、路径不安全、目标在工作区外、符号链接、隐藏文件、扫描不完整和无法重新验证的项目都不得成为可清理候选；扫描不完整时可以展示只读结果，但必须禁止移至系统回收站。
3. **结果有作用域。** 焦点页属于当前文档；“未引用”始终表示“位于该文档图片目录且未被本次工作区扫描识别为引用”，不宣称工作区外没有引用。
4. **不干预文档生命周期。** 不在保存、自动保存、关闭、恢复、外部变化、watcher 或图片上传完成时自动扫描或删除。
5. **文件操作留在主进程。** renderer 只展示扫描 DTO 与发出明确意图；遍历、路径规范化、重新验证和移入回收站均由主进程完成。
6. **保持 Markdown 优先。** 资源关系来自普通 Markdown/HTML 中的本地引用，不引入独立资源所有权表、二进制嵌入或专有索引格式。

## 4. 范围与非目标

### 4.1 包含范围

- 仅当活动文档已有 `filePath`、文件在磁盘上存在，且其 canonical path 位于当前 sidebar 已打开工作区根目录内时启用入口。临时、未保存、已不存在、没有工作区或位于工作区外的文档中，“工具 > 资源健康”必须灰色不可用。
- 扫描以当前文档最后一次成功保存到磁盘的内容为准，忽略编辑器中尚未保存的内容；打开焦点页后不因输入、撤销或 recovery 内容自动改变结果。
- 从当前文档目录下由当前 `pasteImagesDir` 解析出的图片目录枚举候选；若用户后来改过该设置，旧目录的孤儿资源允许漏报，不能由此扩大删除范围。
- 为保护共享图片，扫描工作区内可读取且可安全解析的 Markdown/HTML 文档中的本地引用；候选只要被任一此类文档引用，即不显示为未引用。这里的工作区扫描只用于保护当前文档图片目录中的候选，并不枚举或管理整个工作区的任意资产。
- 解析相对路径、URL 编码、查询参数与 fragment，并以各引用文档所在目录解析物理路径。
- 展示未引用图片候选、当前文档缺失图片引用、已保存版本时间、扫描范围、候选总大小和“存在工作区外引用盲区”的说明。
- 对未引用候选提供缩略预览、相对路径、大小、修改时间、在文件管理器中显示、复制路径和用户选中的“移至系统回收站”。
- 对缺失引用展示目标路径、原始引用和当前文档内的引用位置；用户可逐项删除仍存在于当前编辑器的引用。

### 4.2 明确不包含

- 不自动删除、不提供“保存后清理”或“关闭后清理”，也不依图片上传时间推断所有权。
- 不扫描、删除或报告工作区外的资源；工作区内文档指向外部路径时只作为“外部引用未纳入扫描范围”统计信息。非 Markdown/HTML 文档也不参与引用提取，因此不能证明它们未引用候选图片。
- 不处理思源笔记的属性视图、数据库、笔记本加密、同步历史、OCR、PDF 标注或资源索引。
- 首版不把任意附件、音视频、压缩包或未知二进制作为可清理对象。图片候选只覆盖当前本地资源策略明确允许、且当前设置下可由 Vditor Desktop 正确渲染的本地图片类型；候选分类、预览和资源协议共用同一份受控扩展名/MIME/签名策略。SVG 仅在现有 SVG 图片渲染设置开启时参与候选、预览和缺失引用；关闭时不将 SVG 列为可清理候选。
- 不自动修改 Markdown 链接、自动修复缺失资源、移动资源目录或直接重写磁盘文件。
- 不把系统回收站当作应用内版本历史；恢复由操作系统提供，Desktop 只如实提示该边界。

## 5. 用户体验

### 5.1 入口与页面

在现有应用主菜单内新增本地化的“工具”子菜单，其第一个子项为“资源健康”。该入口只对当前已保存、仍存在且位于当前 sidebar 工作区内的 Markdown 文档可用。临时、未保存、已不存在、没有工作区或位于工作区外的文档中显示为灰色不可点；资源健康页面也必须以灰色占位与明确文案提示“资源健康仅检查当前工作区内的文档。请切换至文档所在工作区后重新打开文档。” 点击后在主窗口内打开与设置页同类的独立页面，而不新建 Electron 窗口；它只在用户主动打开或按“重新扫描”时工作，不能在应用启动或编辑输入期间后台遍历工作区。

资源健康页不是通用文件管理器：顶部和结果均围绕一次特定的“当前文档 + 已保存版本 + 工作区”扫描表达，危险操作只在用户明确选择候选后出现。离开该页面、切换活动文档或工作区时丢弃本次扫描 revision；返回编辑器后不在后台继续扫描。

页面顶部必须包含下列稳定信息：

- 标题与“检查当前文档与本地图片资源之间的关系”的简短说明；
- 已完成、扫描中、失败或已过期的状态；成功状态同时显示当前文档名、相对工作区路径、最后一次成功保存时间和工作区名；
- “重新扫描”操作；当前文档再次成功保存、工作区/活动文档改变或磁盘版本变化后，将结果改为“已过期，请重新扫描”，不得继续显示为有效的“扫描完成”；
- 显眼但不阻塞操作的限制提示：当前编辑器的未保存改动不参与扫描，工作区外文档仍可能引用候选图片。
- 若扫描不完整，显示明确、不可忽略的操作阻断提示：“工作区内有 {count} 份 Markdown/HTML 文档无法读取或安全解析。为避免删除仍被这些文档引用的图片，已禁止移至系统回收站。你仍可查看本次已扫描到的结果。” 提示同时汇总无权限、读取失败、超出大小限制、超出扫描上限与解析不确定等原因；不暴露不必要的绝对路径。

### 5.2 顶层状态覆盖层

- 用户打开资源健康页后，只要扫描尚未完成，整个页面内容必须变灰、禁止交互，并在页面最顶层绘制覆盖层。覆盖层仅展示本地化的无障碍状态文本和关闭按钮，不再承载加载动画；扫描状态卡仍显示“正在扫描”，并由 `aria-busy` 与底层 `inert` 表达状态。
- 若活动文档不在当前 sidebar 工作区内、没有工作区，或文档不再存在，页面同样保持灰化，并以最顶层错误覆盖层替代扫描文本。覆盖层使用 `src/renderer/assets/notification/warning.svg`，展示“资源健康仅检查当前工作区内的文档”的错误提示，以及“请切换至文档所在工作区后重新打开文档查看资源情况”的建议性文字。
- 覆盖层必须拥有适当的 `role`、焦点管理和 `aria-busy`/错误状态；扫描成功、失败、取消、离开页面或工作区/活动文档变化时清理事件监听与焦点状态。它不能只是视觉遮罩：处于扫描或不可用状态时，底层的重扫、候选选择、预览、复制和回收站操作均不得响应。

#### 5.2.1 持续资源分析图标动画实现契约

原 analyzing image 动画不再作为短生命周期 loading 动画使用，而是放置在扫描状态卡中，替换原 `check-circle.svg`。资源健康页打开期间该图标持续播放，使用 `var(--accent)` 主题色，尺寸为 64 × 64 px，明显大于原 1em 图标；图标保持 `aria-hidden="true"`，未保存提示继续使用静态 `lightbulb.svg`。

动画仍由原生 DOM/CSS 组成：底层像素化图片外框（外框 path 加源文件中的 58 个 `rect` 片段）、上层完整图片路径的背景色遮罩和横向扫描线共同组成三层视觉效果。遮罩和扫描线保持源动画的 2.5 秒运动段、相同缓动，并在左右端点各停留 0.2 秒（CSS 实现总周期为 2.9 秒），按源动画的镜像方向循环；遮罩背景必须匹配扫描状态卡，避免出现矩形色块。`prefers-reduced-motion: reduce` 时停止遮罩和扫描线动画。扫描覆盖层中的文字保持静态，不再使用 TextShimmer。

### 5.3 未引用候选

- 候选默认不选中；不提供一键、无预览的“全部删除”。
- tab 标题显示候选数量；tab 下方显示候选数量、总大小、图片目录，以及本次扫描的 Markdown/HTML 文档数和跳过的受保护项目数。
- 主列表按行显示复选框、缩略图、文件名、工作区相对路径、大小、修改时间和行级更多操作。图片预览不可用时以明确的不可用占位替代，不能以空白行隐藏失败。
- 鼠标 hover 文件名时用 tooltip 显示图片缩略图和完整相对路径；选择某行后，在右侧保留固定预览面板，展示更大缩略图、路径、复制路径与“在文件管理器中显示”。tooltip 只用于快速扫览，固定面板用于用户执行回收站操作前确认目标。
- “移至系统回收站”只作用于用户显式勾选的项目；每次均显示危险确认框，列出数量、总大小、候选明细、重新验证说明和“工作区外引用无法证明不存在”的提示，不能被任何“不要再提示”选项绕过。
- 默认显示范围提示：资源健康仅检查当前工作区内可读取且可安全解析的 Markdown/HTML 文档，对当前文档图片目录中的候选图片进行引用检测；它不能确认工作区内不可访问、读取失败、超出扫描限制或无法安全解析的文档，以及非 Markdown/HTML 文档和工作区外文件是否仍引用这些图片。用户可勾选“我已了解，后续不再显示此范围提示”。只有在该次危险确认实际确认时，才将 `resourceHealthTrashScopeWarningEnabled = false` 持久化到 `config.toml` 的 `[files]`；取消不改变此偏好。
- 文件设置页提供“删除前显示资源健康扫描范围提示”开关，供用户恢复默认提示。该开关只控制上述扩展范围提示，不影响每次危险确认、扫描不完整阻断、扫描 revision 过期检查或主进程逐项重新验证。
- 底部固定操作条显示已选择项目数和“只处理已明确选择的项目，操作前将重新验证”的说明。未选择项目、扫描中、扫描不完整、结果过期或重新验证失败时，“移至系统回收站”保持禁用。
- 执行前主进程重新验证每个候选仍在工作区内、不是符号链接、仍未被最新磁盘扫描引用，且文件身份/修改时间未变化；任一验证失败的项目保留并报告原因。
- 操作完成后重新扫描并刷新列表；部分失败不得掩盖已成功或未处理的项目。

### 5.4 缺失引用

- 缺失项不提供自动新建、自动下载或自动改写链接。
- tab 标题显示缺失目标数量；列表按目标聚合，显示文件名、原始引用/解析路径、当前文档内的全部引用位置和受影响引用数。
- 同一目标在当前文档中有多个引用时合并展示，并列出全部引用位置；用户可以展开条目核对每一处，而不是只能看到一个笼统计数。
- 每个条目可执行“删除缺失资源在本文档中的引用”，也可在勾选多个条目后执行同名批量操作。确认框必须显示将删除的目标、引用数和 Markdown 片段；操作前必须重新解析当前编辑器内容，只删除仍与扫描条目完全匹配的引用。已经由未保存编辑移除、替换或改变的引用跳过并报告。
- 删除操作只经 Vditor 当前编辑路径修改内存正文、保留 undo 并标记文档未保存；不得自动写盘，也不得用整篇 `getValue()` / `setValue()` 回写伪造编辑。
- 远程 URL、`data:` URL、锚点、工作区外本地路径和解析不确定的引用不归入“缺失图片”，避免把非本地资源误报为损坏。

## 6. 扫描与分类契约

### 6.1 输入快照

扫描输入是当前文档最后一次成功保存的磁盘内容，以及当前工作区其他可读取且可安全解析 Markdown/HTML 文档在某一时刻的磁盘快照；它不读取或持久化 Vditor DOM、选区、撤销记录、recovery snapshot 或运行时句柄。当前编辑器的未保存内容有意不参与该快照。

扫描 revision 绑定当前文档 canonical identity、其最后成功保存的文件 identity/修改时间、工作区 identity 与图片目录。当前文档保存成功、工作区切换或磁盘版本改变后，旧 revision 过期，不能用于回收站操作。

### 6.2 引用提取

实现必须建立可单测的 Markdown/HTML 本地资源提取器，而非使用宽泛正则直接搜索文件名。至少覆盖：

- 内联 Markdown 图片和普通链接；
- 引用式图片/链接及其定义；
- HTML `img` 的 `src`，以及会指向本地图片的等价资源属性；
- URL 编码路径、可忽略的 query/fragment、空格与常见标题语法；
- 代码围栏、行内代码和转义文本不应被误认为资源引用。

提取器无法安全理解的 Markdown/HTML 必须保守处理：关联路径不进入可清理候选，或将本次扫描标记为“存在未解析内容，不能用于回收站操作”。解析规则与 fixture 必须独立测试，不能依赖 Vditor 私有 DOM。

### 6.3 路径与候选规则

- 所有路径通过 Node `path`/URL API 解码、规范化、realpath 并校验位于工作区根目录内；不得以字符串前缀判断包含关系。
- 资源目录候选仅枚举其直接子文件，不递归进入二级目录；二级目录及其内容不显示为未引用候选，也不成为回收站操作目标。
- 不跟随符号链接。若资源目录的直接子项中发现符号链接，本次扫描立即标记为不完整，符号链接不显示为未引用候选，并禁止移至系统回收站；页面提示用户“当前图片目录内有符号链接。为保护文件安全，已禁止移至系统回收站。请将符号链接替换为原始图片后重新扫描。”
- 工作区引用扫描保留隐藏用户 Markdown/HTML 文档，以保护可能被它们引用的图片；但 `.git`、`.hg`、`.svn` 与 `.cache` 控制目录不参与该扫描。无法 stat 的条目与工作区根以外的路径均跳过并计入说明。
- 枚举候选时仅接受当前本地资源策略允许的图片类型，并通过相同的受控扩展名/MIME/签名策略确认；不把 Markdown、配置、数据库或未知文件列为可清理资源。不得仅因 Vditor 上传入口接受 `image/*` 就将某个格式视为可安全预览或清理。
- 某个图片只要被任一工作区 Markdown/HTML 本地引用解析到，即为已引用；目录式引用须保守地保护其所有后代。
- 缺失项以“当前文档引用位置 + 原始引用 + 解析后的工作区内目标”表达；候选以相对工作区路径表达，renderer 不接收任意绝对路径作为可写入能力。

#### 6.3.1 符号链接与二级目录

候选扫描的删除范围有意收束为当前文档图片目录的直接常规图片文件。二级目录不递归扫描，其内容既不会显示在未引用列表，也不能被本功能移至系统回收站。

扫描不跟随符号链接。资源目录直接子项中一旦发现符号链接，即停止候选扫描并将结果标记为不完整：该链接不会显示为候选，“移至系统回收站”保持禁用，页面提示用户将符号链接替换为原始图片后重新扫描。该策略减少了清理范围和意外跟随链接的风险，但不改变系统回收站 API 仅接受路径字符串这一跨进程限制；因此它是保守的产品边界，而不是目录句柄级原子文件操作的替代品。

### 6.4 资源与读取上限

资源健康按“解析引用文本”和“枚举图片资产”分开计量：图片本体大小不计入 Markdown/HTML 的读取预算。首版将下列安全上限作为主进程内部常量，而非用户设置；命中任一上限时停止继续扫描，返回带限制原因的只读部分结果，并禁止本次扫描 revision 的所有回收站操作：

| 对象                      | 首版上限与处理                                                                               |
| ------------------------- | -------------------------------------------------------------------------------------------- |
| Markdown/HTML 源文件数    | 最多 5,000 份；超过后停止扫描。                                                              |
| 单份 Markdown/HTML 源文档 | 最多读取 4 MiB；超过时不读取并记录原因。                                                     |
| Markdown/HTML 累计读取量  | 最多 64 MiB；达到后停止扫描。                                                                |
| 图片目录条目数            | 最多枚举 10,000 项；超过后停止扫描。                                                         |
| 扫描总耗时                | 30 秒；超时取消尚未完成的工作并记录原因。                                                    |
| Markdown/HTML 并发读取    | 最多 4 份，避免手动扫描耗尽主进程 I/O 资源。                                                 |
| 图片文件大小              | 分类不读取整张图片，不设图片总大小或单张大小上限；仅检查元数据及受控格式所需的有限头部。     |
| 缩略预览                  | 按可见行惰性加载；源文件超过 64 MiB 时显示“预览不可用”，但若其余候选条件满足仍可展示和选择。 |

## 7. 架构与安全边界

### 7.1 主进程服务

新增一个独立的资源健康服务，负责枚举、引用提取、路径解析、候选/缺失分类、文件元数据、扫描 revision 与回收站前重验证。它不属于 `DocumentController`、`ImageController` 或文件 watcher；这些现有模块继续只负责文档安全交易、图片写入/插入和已打开文件状态。

服务返回版本化 DTO，例如：

- `ResourceScanSummary`：当前文档 canonical identity、最后成功保存版本、工作区标识、扫描 revision、完成时间、候选/缺失数量与大小、跳过/限制原因；
- `UnusedImageCandidate`：受控候选 ID、工作区相对路径、显示名、大小、修改时间、预览是否可用；
- `MissingImageReference`：原始引用、工作区相对目标、当前文档内的稳定引用标识/位置；
- `ResourceActionResult`：每一候选的 `trashed`、`revalidatedAsReferenced`、`changedSinceScan`、`outsideWorkspace`、`unsupported` 或基础设施失败结果。

扫描 revision 只在主进程内保存短生命周期结果；renderer 只能将该 revision 与候选 ID 回传，不能提交任意文件路径要求删除。

### 7.2 IPC、preload 与 renderer

新增窄 IPC 能力：为当前已保存文档扫描资源、打开候选所在位置、以及将指定扫描 revision 的指定候选移至系统回收站。主进程必须验证 trusted renderer、请求形状、候选 ID、扫描 revision、当前文档/工作区 identity 和每个操作前的文件/引用状态。删除缺失引用是 renderer 的明确编辑意图，经 adapter/Vditor 的语义编辑 API 完成，而不是主进程文件写入能力。

preload 只暴露这些命名方法；renderer 不导入 Node，也不获得目录遍历、任意读取、任意删除或通用 shell 能力。用户可见文案进入 `locales.js` 的 English、简体中文和繁体中文。

### 7.3 Renderer 模块边界

资源健康页面由独立的 `ResourceHealthController`（及其按需拆分的纯视图/状态辅助模块）拥有：页面进入/离开、顶层覆盖层、扫描请求/取消、revision 过期、候选选择、预览、确认与页面 DOM listener 的生命周期。它通过窄 bridge 和语义 adapter API 协作，不能读取 Vditor 私有 DOM。

`app-composition.js` 只负责创建该 controller、注入窄依赖，并保留诸如“从菜单打开资源健康页”这类小型命名协调回调；不得在 composition 层新增扫描状态、直接 Store 写入、bridge 调用、DOM 操作、计时器、事件监听、文件遍历或回收站业务。功能实现不得为了接线方便向 composition 堆积领域函数或状态转换。

### 7.4 生命周期

- 离开资源健康页、活动文档或工作区切换、当前文档成功保存或应用退出时取消扫描/丢弃旧 revision；迟到结果不能覆盖新文档页面。
- 扫描运行时不得改变已有 workspace watcher、打开文档 watcher 或资源授权根。
- 回收站操作只使用 Electron/Node 的跨平台 API；不得通过 shell 命令实现。
- 将文件移至系统回收站后，必要时刷新工作区树和资源列表，但不向打开 Markdown 注入内容、不改变保存基线或触发自动保存。

## 8. 分阶段实施

### 阶段 A：只读资源健康扫描

1. 先完成纯路径解析、Markdown/HTML 引用提取、候选分类和缺失分类的单元测试；测试 Windows、macOS 与 Linux 路径形态、编码 URL、查询/fragment、代码围栏、HTML、工作区外路径、符号链接、解析失败、当前本地资源策略允许的图片类型与 SVG 设置边界。
2. 实现主进程只读服务与版本化 DTO，并为工作区切换、扫描取消、过期结果、不可读目录、扫描不完整操作阻断和各项内部资源上限补充测试。
3. 接入窄 IPC/preload、应用主菜单内的工具子菜单与设置页同类的资源健康页；完成三语、扫描时顶层灰化和静态状态覆盖、扫描状态卡中的持续 analyzing image 动画、工作区外/临时文档的 `warning.svg` 顶层错误覆盖、空状态、扫描中/失败/不完整状态、hover 缩略预览和 Electron E2E。
4. 人工验证共享 `assets/`、自定义 `pasteImagesDir`、相邻 Markdown、HTML 图片、工作区外引用、已保存版本扫描及未保存编辑不参与扫描等场景。

阶段 A 不包含任何删除/回收站操作；完成后用户可安全理解“候选”范围和实际扫描结果。

### 阶段 B：受控移至系统回收站

1. 为候选选择、确认、扫描 revision、修改时间/文件身份变化、重新出现引用、扫描不完整、部分失败与工作区切换补充行为测试。
2. 实现主进程逐项重新验证及系统回收站调用；不提供原始路径删除、递归目录删除或绕过确认的批量能力。
3. Electron E2E 验证：只处理所选候选；已引用/变更/工作区外/过期 revision 候选被拒绝；用户取消不产生副作用；完成后列表重扫。另验证删除缺失引用只影响仍匹配当前编辑器的条目、保留 undo 且不自动保存。
4. Linux 手测系统回收站可恢复性；Windows/macOS 的原生回收站、Finder/Explorer 恢复和 macOS 原生菜单验证统一按 [`docs/03-CROSS-PLATFORM.md` §14](03-CROSS-PLATFORM.md#14-025-resource-health-deferred-windowsmacos-native-verification) 执行并记录证据。

## 9. 验收标准

1. 临时、未保存、已不存在、没有工作区或位于当前 sidebar 工作区外的当前文档中，“工具 > 资源健康”灰色不可用，资源健康页显示推荐切换工作区的灰色占位，且不会访问任意最近文件目录。
2. 扫描只依据当前文档最后一次成功保存版本；当前编辑器未保存内容不改变结果，当前文档保存成功后结果过期。
3. 当前文档图片目录中、已被任一工作区 Markdown/HTML 引用的图片不会出现在未引用候选；同一图片被多个文档引用仍只计算为已引用。
4. 当前文档已保存版本中的丢失图片引用可定位到全部引用位置；远程、`data:` 和工作区外引用不误报为缺失。
5. 代码围栏、URL 编码、query/fragment、引用式语法、HTML、平台路径、当前本地资源策略允许的图片类型与 SVG 设置边界有自动化覆盖；解析不确定时不产生可清理候选。
6. 删除缺失资源引用前重新验证当前编辑器；只删除仍匹配的引用，保留 undo、标记未保存且不自动写盘。
7. 工作区中任一 Markdown/HTML 无权限、读取失败、超出大小/扫描上限或无法安全解析时，页面显示明确的操作阻断提示并允许查看部分结果，但禁止全部回收站操作。
8. 回收站操作只处理用户勾选的、当前扫描 revision 中仍满足候选条件的文件；每个操作前重新验证，失败项目不被删除。
9. 回收站操作使用系统回收站且不会修改 Markdown、session、recovery、保存基线、undo 或 Vditor 实例。
10. 每次回收站操作均保留危险确认；范围提示可以在确认时由用户选择不再显示，但不得绕过确认、扫描不完整阻断、过期检查或主进程重新验证。该选择作为 `[files].resourceHealthTrashScopeWarningEnabled` 布尔偏好持久化，设置页可以恢复提示。
11. 图片本体大小不消耗 Markdown/HTML 读取预算；扫描不预读整个图片目录，缩略图按可见行惰性加载，超过预览上限时明确显示不可用占位。
12. 扫描中页面以顶层静态状态覆盖层灰化并禁止底层操作；持续 analyzing image 动画固定显示在扫描状态卡中，替换 `check-circle.svg`。工作区外、无工作区或文档不存在时，以包含 `warning.svg` 和切换工作区建议的顶层错误覆盖层灰化页面。两类覆盖层的可访问状态、焦点与清理均有自动化覆盖。
13. 所有新文案完成三语；页面、扫描取消、工作区/当前文档切换、预览、内部资源上限、不完整扫描操作阻断与回收站行为有单元及 Electron E2E 覆盖。
14. 专项完成后，更新 `docs/01-CODE-STRUCTURE.md`、`docs/03-CROSS-PLATFORM.md`、`CHANGELOG.md`、本 Tracker 和本专项的实际证据；完整回归按 0.2.5 收口流程执行。

## 10. 启动条件与施工顺序

本专项在批次 9 完成、用户手测与当前 HEAD 的完整验证收口后启动。它不回填批次 9 的 renderer composition 迁移，也不与批次 9 的未提交改动混合实现。

启动时先以本文件第 8 节阶段 A 为施工卡：核对当前 `ImageController`、活动文档/保存状态、工作区树、文件 bridge、资源协议、工具菜单与资源健康页面的实际边界；再建立纯函数/主进程服务测试，最后接入 UI。阶段 A 经用户手测后才可开始阶段 B。
