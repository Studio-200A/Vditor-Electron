## 2. 核心用户路径行为清单

计划 §14 的八类路径如下；每项标注入口、关键函数、状态写入、DOM 更新与清理。

### 2.1 启动与 session 恢复

- 入口：`DOMContentLoaded → init()`（5359-5413）。
- 顺序：资源完整性检查 → 读取 `settings`/`defaultSettings` → `applyLocale` → `setupEvents`（一次性注册全部全局监听）→ 侧边栏宽度下限与布局 → `applyPresentationSettings` → `applyTheme(resolveTheme())` → 版本号文本 → 按 `restoreWorkspace` 恢复工作区（`setWorkspace`）→ 按 `restoreTabs` 恢复标签（`openPaths` + 激活 `activeFilePath`）→ `restoreRecoverySnapshots`（2397）→ 空标签时创建工具栏预览 → `persistSession` → `body[data-app-ready]` → `rendererReady()`。
- 失败路径：`Vditor`/adapter/bridge 缺失时整体替换 `body` 为致命错误页（5360-5364）。
- 清理：启动期注册的资源均为应用生命周期级，无运行期销毁路径（0.2.0 无统一 dispose；0.2.5 批次 1 将建立 init/dispose 协议）。

### 2.2 新建、打开、保存、另存和关闭

- 新建：`newTab`（1857）→ `createTab`（1664）。上限 20 个标签；未命名编号由 `state.untitledCounters` 生成并经 `untitledCollisionKey`/`nextUntitledNumber` 避让工作区同名项。
- 打开：`chooseFiles`（2848）/拖放（5346）/`onOpenFiles`（4896）→ `openPaths` → `openPath`（1771）：先取 `fileIdentity`，按 identity 或规范化路径去重；未命名标签再次被打开同路径时转为冲突状态（1781-1792）。
- 保存/另存：`saveTab`（2073）→ 每标签 `saveOperation` 串行 → `performSaveTab`（2111），详见 §3.1。
- 关闭：`closeTab`（1882）：未保存确认（`showUnsavedDialog`）或不可用状态确认 → 清理计时器/快照/observer/快捷键监听 → `vditor.destroy()` → `host.remove()` → `releaseDocumentWatch` → `syncLocalResourceRoots` → 激活相邻标签或恢复空态。
- 窗口关闭：`onRequestClose`（5319）：存在未解决 `externalFileState` 时阻止关闭；脏标签逐个保存或整体放弃（放弃时并发 `discardRecoverySnapshot`）。

### 2.3 标签切换和独立编辑模式

- `switchTab`（1862）：归还上一标签工具栏 → 激活 → `ensureEditor` → 挂载工具栏 → 行号/大纲/查找刷新 → `persistSession`。
- 每标签独立 `mode`（`wysiwyg`/`ir`/`sv`）；默认取自 `settings.editMode`，改动默认模式只影响之后的标签（有 E2E 覆盖）。
- 模式切换三条入口：菜单 `handleMenu('mode')` → `rebuildEditor(tab, mode)`（1633）；Vditor 工具栏子菜单 → `prepareVditorModeTransition`（1593）；快捷键 Ctrl/Cmd+Alt+7/8/9 → `handleVditorModeShortcut`（1608）。后两者不重建实例，用 `captureEditorScroll`/`restoreEditorScroll` 保持滚动。

### 2.4 工具栏显示/隐藏

- 基线只有两种工具栏状态：显示 / 隐藏（`视图 > 布局 > 工具栏`，`setLayoutPart`，4670；`toolbarVisible` 布尔）。计划 §14 提到的“浮动工具栏”不在 0.2.0 范围内（见 `30-WISHLIST.md`），Tracker 施工卡中“三种工具栏模式”按基线修正为两种状态。
- 空标签页使用 `createToolbarPreview`（313）渲染禁用的 Vditor 工具栏骨架；首个真实标签就绪后经 `disableToolbarPreview` 交接。
- 工具栏挂载交接：`mountEditorToolbar`（1622）/`restoreEditorToolbar`（1616）在 `#vditorToolbarMount` 与标签 `host` 之间移动 Vditor 工具栏节点；`syncToolbarAvailability`（286）维护 `data-toolbar-pending` 占位；`syncToolbarWrapHeight`（4696）+ ResizeObserver/MutationObserver（5291-5297）维护换行高度补偿。

### 2.5 工作区树、重命名、删除和外部变化

- `chooseFolder`（2853）→ `setWorkspace`（2874）：`workspaceRevision` 防过期 → `setWorkspaceWatch` → `refreshTree`（2899）→ 记录 `recentPaths`/`defaultOpenPath`。
- 树渲染 `appendDirectory`（2945）：扩展名过滤、隐藏文件过滤、深度限制（`workspaceReadDepth`）、符号链接环/工作区外链限制；展开状态按工作区持久化（`persistDirectoryExpansion`，2926）。
- 右键菜单：文件/目录条目 `showTreeMenu`（3175，重命名/删除/在文件管理器显示）；空白处 `showWorkspaceTreeMenu`（3189，更换工作区/新建）。
- 重命名 `renameExplorerItem`（3224）：内联输入校验 → `fileAPI.rename` → `rebaseOpenTabs`/`rebasePathState`（490/499）更新打开标签、最近文件、树展开状态 → `rebindDocumentWatches`（452，两次重试）→ `rebuildRenamedEditors`（477）。
- 删除 `deleteExplorerItem`（3373）：确认对话框 → `fileAPI.moveToTrash` → 受影响标签由 watcher 事件走不可用流程。
- 外部变化：`fileAPI.onChanged → handleExternalChange`（4356），详见 §3.2-§3.4。

### 2.6 主题、字体、缩放和设置热应用

- 六套主题：`classic`、`dark`、`claude-light`、`claude-dark`、`monokai-pro-dark`、`monokai-pro-light`（`src/main/services/app-state.ts:16`）。主题模式三选：`light`/`dark`/`system`（`THEME_MODES`，117）。
- `applyTheme`（790）：写 `document.documentElement.dataset.theme` → 联动内容主题（`light`/`dark` 链接模式）→ 按亮暗选择代码主题偏好 → `vditor.setTheme`（不重建实例）。
- 系统主题变化经 `onSystemThemeChanged`（5307）热应用。
- `applyPresentationSettings`（829）：字体/缩放/行宽/滚动条模式经 CSS 变量与 `setZoomFactor` 应用，不重建编辑器（撤销历史保持，有 E2E 覆盖）。
- 设置保存 `saveSettings`（3995）：表单收集 → `queueSettingsSave` → 差异分类：`VDITOR_INITIALIZATION_SETTINGS`（62-90，27 项）内任一变化 → 全部标签 `rebuildEditor`（保持各标签当前 mode）；`previewMode` 变化 → `setPreviewMode` 热应用（858）；`allowSvgImages` → `reloadImageSources`。
- 实时保存 `scheduleLiveSettingsSave`（4109）：SVG 与 sanitize 两项先弹确认；文本/数字输入 250ms 防抖。

### 2.7 大纲、图片、HTML/PDF 导出

- 大纲：`scheduleOutline`（3399，300ms 防抖）→ `renderOutline`（3404）用 `VDITOR.outlineSnapshot`；折叠状态存 `tab.outlineCollapsed`；点击 `scrollToOutlineHeading`（3502）。标题变化由 `after()` 中 `observeOutlineChanges`（1344）驱动。
- 图片：上传 `handleImageUpload`（3715，要求已保存文档；写入 `./assets` 并插入相对链接）；粘贴/上传压缩 `compressImage`（3742，按 `imageMaxWidth`/`imageQuality`）；相对图片由 `observeRelativeImageSources`（1339）+ `localResourceBase`（549）重绑定到 `local-file:` 协议。
- 导出：`exportHTML`（3883）用 `normalizeExportBody`（3801）把 `local-file:`/`app:` 资源改写为可移植相对路径；`exportPDF`（3899）另经 `embedExportImages`（3847）内嵌 base64 图片；正文快照在打开保存对话框之前获取（`exportBodySnapshot`，3767，有 E2E 覆盖）。

### 2.8 未保存关闭确认、异常恢复和窗口事件

- 关闭确认：标签级 `showUnsavedDialog`（220，保存/放弃/取消）；窗口级 `onRequestClose`（5319）。
- 恢复快照：`scheduleRecoverySnapshot`（2318，500ms 防抖，`schemaVersion: 2`）→ `appAPI.saveRecovery`；保存成功且无新输入时 `discardRecoverySnapshot`（2342）。
- 重启恢复 `restoreRecoverySnapshots`（2397）：`getRecoveryCandidates` → 逐个 `restoreRecovery`；`diskState` 为 `unchanged` 时合并回同 identity 的会话标签或新建带 `filePath` 的标签；`changed`/`unavailable` 时新建恢复标签并显示恢复横幅（`updateRecoveryBanner`，2651）。
- 恢复动作：`saveRecoveredVersion`/`saveRecoveredAs`/`discardRecoveredVersion`（2672-2685）。
- 窗口事件：最小化/最大化/关闭按钮、双击标题栏最大化、`onMaximizedChanged`（5315）、`onFullscreenChanged`（5310，F11 切换，全屏菜单 Alt 显隐）。

### 2.9 三项安全回归（§14 必保）

1. **watcher ready + reconciliation**：主进程 `file-watch-service` 负责“创建 → ready → 单次磁盘读取 → 实时事件”；renderer 只消费 `onChanged`。ready 前事件与重绑空窗由主进程补偿读取覆盖（单元 `tests/unit/file-watch-service.test.ts`；E2E “reconciles a renamed document after repeated watcher rebind failures”）。
2. **canonical identity**：`fileIdentity()` 结果用于去重、保存队列（`queueSaveForIdentity`，2088）、冲突/不可用状态（均携带 `identity` 字段）、watcher 释放/重绑（`releaseDocumentWatch`，430）；显示路径仅用于展示。符号链接别名由 E2E “keeps external conflict protection when Save As selects a symlink alias” 覆盖。
3. **单次读取基线**：`performSaveTab` 的解码正文与 `expectedContent` 来自同一次读取路径（同路径保存用内存 `expectedSavedContent`，否则一次 `readFile`），安全写入器在替换前复核字节（`safe-file-writer.ts`；契约见 `docs/05-FILE-SAFETY.md` §7）。

## 3. 安全关键状态转换表

以下五组转换是批次 3-4 的安全基线。`持久化结果` 指落盘/落配置的内容；`清理结果` 指计时器、监听、快照与 watcher 的收尾。

### 3.1 保存（普通保存 / 另存 / 自动保存）

| 步骤 | 输入/条件 | 状态变化 | 持久化结果 | 清理结果 |
| --- | --- | --- | --- | --- |
| 串行化 | 任意保存请求 | `tab.saveOperation` 链式串行；目标 identity 经 `queueSaveForIdentity` 全局串行 | — | 队列完成后删除 Map 条目 |
| 目标解析 | 无路径或另存 | — | 弹 `saveFileDialog` | — |
| 占用检查 | 另一标签持有同 identity | 无 | 拒绝（`savePathAlreadyOpen`） | — |
| 不可用检查 | `externalFileState` 且非重建流程 | 无 | 拒绝（先解决不可用） | — |
| 冲突检查 | `externalConflict` 命中目标 identity | 无 overwrite 参数 → 拒绝或转覆盖确认；版本不匹配 → `changedAgain` | — | — |
| 基线复核 | 同 identity 原地保存 | 文件不存在 → `preserveUnavailableTab('deleted')`；内容 ≠ `expectedSavedContent` → 建立冲突；读取失败 → `preserveUnavailableTab('unreadable')` | — | 冲突时清除 `saveTimer` |
| 写入 | 换目标时先 `suspendDocumentWatches` | 内容按 `lineEnding` 归一化；`expectedContent`/`expectedAbsent` 单读确定 | `writeDocument`（安全写入 + 字节复核 + rename） | 失败时 `rebindDocumentWatches` |
| 成功 | — | 重绑 `filePath`/`fileIdentity`/`title`/`baseDir`；`savedContent`/`expectedSavedContent` 更新；清除冲突与不可用；`encoding='utf-8'` | `recentFiles` 更新；session 持久化；树刷新；恢复快照丢弃或重排 | 释放旧路径 watch → 新路径 `watchTabDocument`；`baseDir` 变化时 `rebuildEditor` |

自动保存：`onEditorInput`（2034）在 `autoSave` 开启、有路径、脏且无冲突/不可用/忽略时，按 `autoSaveDelay` 重置 `saveTimer`；冲突、不可用或被忽略期间自动保存暂停。

### 3.2 外部修改与冲突

| 输入 | 前置状态 | 结果状态 | 用户动作 | 持久化/清理 |
| --- | --- | --- | --- | --- |
| `change` 事件，内容 = `expectedSavedContent` | 任意 | 清除冲突与忽略标记 | — | — |
| `change` 事件，内容不同，文档干净且未忽略 | `!modified` | 静默重载（`setValue`），`lineEnding`/`encoding` 同步 | — | 提示 `external.reloaded` |
| `change` 事件，内容不同，文档脏 | `modified` | `externalConflict{kind:'modified', identity, content, version+1}` | 重载 / 另存 / 覆盖 / 忽略 | 清除 `saveTimer`（暂停自动保存）；横幅显示 |
| 覆盖确认 | 冲突中 | 版本复核通过后按普通保存写入 | `确认覆盖` | 成功后清除冲突 |
| 忽略 | 冲突中 | `externalChangeIgnored = true`，横幅隐藏，冲突保留 | 之后仍可另存；再遇保存走覆盖确认 | — |
| 重载 | 冲突中 | 采用外部内容，`modified=false`，同 identity 标签全部同步 | `重载` | 大纲刷新；session 持久化 |

### 3.3 外部删除 / 不可读 / 重新出现

| 输入 | 结果状态 | 用户动作 | 持久化结果 | 清理结果 |
| --- | --- | --- | --- | --- |
| `unlink` | `externalFileState{kind:'deleted', identity, clipboardContent}` | 另存 / 保留为未命名 / 重建 / 关闭 | 立即写入恢复快照 | 清除 `saveTimer`/`recoveryTimer`；内存正文保留；自动保存暂停 |
| `unreadable` | `externalFileState{kind:'unreadable', error}` | 另存 / 保留为未命名 / 关闭（重建按钮隐藏） | 同上 | 同上 |
| 重新出现（`change` 且已有 `fileState`） | `kind:'reappeared'`，携带新内容 | `重载` 采用磁盘内容并丢弃恢复快照 | `discardRecoverySnapshot` | 清除冲突/不可用 |
| 保留为未命名 | 解绑路径与 identity | — | session 持久化 | `releaseDocumentWatch`；`syncLocalResourceRoots`；重排恢复快照 |
| 重建 | 以 `recreateFileState=version` 走保存，`expectedAbsent=true` | 确认后 | 文件重建；删除前的 `clipboardContent` 写回剪贴板（失败单独提示） | 恢复正常保存链路 |
| 关闭 | 确认后 `closeTab({discard:true})` | — | 丢弃恢复快照 | 完整标签清理 |

窗口关闭前存在任何未解决 `externalFileState` 时，`onRequestClose` 阻止退出并切换到该标签提示。

### 3.4 工作区根删除

| 输入 | 结果 | 持久化/清理 |
| --- | --- | --- |
| 工作区作用域 `unlink`/`unlinkDir` | `rebaseOpenTabs(path, path)` 找出受影响打开文档 → 逐个 `preserveUnavailableTab('deleted')` | 打开文档进入恢复范围；`renderTabs`/`updateActiveUI`/`persistSession` |
| 被删的是工作区根本身且确认不存在 | `setWorkspace('')` | 清除工作区 watch 与树；`defaultOpenPath` 清空 |
| 其它工作区事件 | `treeTimer` 300ms 防抖后 `refreshTree` | 计时器置空 |

未打开的文件不进入后台恢复范围（§4.1.1）。

### 3.5 异常退出恢复（recovery）

| `diskState` | 重启行为 | 用户动作 | 持久化/清理 |
| --- | --- | --- | --- |
| `unchanged` | 合并回同 identity 的会话标签（`setValue` 或 `pendingEditorContent`）；无会话标签则带原路径新建 | 继续编辑 / 保存 / 放弃 | 保存成功且无新输入 → 丢弃快照；横幅 `recovery.restored` |
| `changed` | 新建恢复标签（标题加恢复标记），不绑定磁盘内容 | 保存 / 另存 / 放弃 | 保存走冲突保护（磁盘已变）；横幅 `recovery.changed` |
| `unavailable` | 新建恢复标签 | 另存 / 放弃（保存按钮隐藏） | 横幅 `recovery.unavailable` |

快照内容仅含可序列化字段（`schemaVersion: 2`，2296-2310）；Vditor 实例、DOM、observer、timer 均不进入快照。主进程侧由 `RecoveryStore` 做版本/大小/编码边界校验（`tests/unit/recovery-store.test.ts`）。

## 4. 各迁移域链路图（事件/输入 → 状态 → DOM → 清理）

标记说明：**多写者** = 同一状态有多个业务写入点；**延迟补偿** = 先执行一次再由 timer/rAF/observer 修正；**fallback** = 失败降级路径；**重叠监听** = 同一事件多条相近链路。这些是 §4.6 要求列出的重构重点。

### 4.1 本地化与对话框（批次 2）

- 链路：`applyLocale`（234）→ `state.locale` → 全量静态文案 `data-i18n` 替换 + 动态 `t()`。
- 确认对话框：`showConfirmDialog`（185）/`confirmDialog`（216）→ `confirmResolver` 单例 Promise；拖拽由 `setupConfirmDialogDrag`（4313）注册 window mousemove/mouseup（瞬时，mouseup 自清理）。
- 消息：`showMessage`（564）→ `messageTimer`（4s 自动隐藏）；临时文档通知 `showTemporaryDocumentNotice`（575）→ `temporaryDocumentNoticeTimer`。
- 风险：`confirmResolver` 单例（同时只能有一个对话框）；消息计时器由多入口共享。

### 4.2 主题与展示（批次 2）

- 写入者：`applyTheme`（790）、`handleMenu('theme')`（4481）、`selectStatusThemeMode`（2596）、`handleVditorToolbarClick` 的 code-theme/content-theme 分支（1484-1504）、`saveSettings`（3995）、`onSystemThemeChanged`（5307）。→ **多写者**：`settings.theme`/`systemTheme`/`lightTheme`/`darkTheme`/`codeTheme`/`contentTheme` 六字段分散写入，均经 `queueSettingsSave` 持久化。
- DOM：`documentElement.dataset.theme`、每标签 `host.dataset.contentTheme`（`syncContentThemeHosts`，778）、设置表单代码主题选项过滤（`syncCodeThemeSelect`，751）、Vditor 工具栏主题按钮过滤（`syncCodeThemeMenus`，764）。
- 延迟补偿：content-theme 选择 light/dark 后 `setTimeout(0)` 再 `applyTheme`（1498-1503）；`after()` 回调中重读当前主题防止过期菜单过滤（1381-1384，有注释说明）。
- 展示设置：`applyPresentationSettings`（829）只写 CSS 变量与 `setZoomFactor`；`editorTextWidth` 滑杆另有独立 `oninput` 直写变量（5038）→ **多写者**（同一 CSS 变量两处写入）。

### 4.3 工具栏与布局（批次 5/8）

- 挂载交接：`mountEditorToolbar`/`restoreEditorToolbar` 双向移动同一 Vditor 节点；`closeTab` 直接清空挂载点 `innerHTML`（1931）。→ **多写者**：`#vditorToolbarMount` 内容。
- 高度补偿：`syncToolbarWrapHeight`（4696）由 ResizeObserver（5291）、MutationObserver → `scheduleToolbarWrapHeight` 双 rAF（5292、4721）、`after()` 回调、`syncToolbarAvailability` 多路触发 → 收敛为单一测量函数（有意合并，但触发点多）。
- 工具栏预览：`createToolbarPreview`（313）/`disableToolbarPreview`（340）/`destroyToolbarPreview`（301）；`saveSettings` 后空标签需重建预览（4075-4078）。
- 侧边栏：`toggleSidebar`（4837）用类状态机（`sidebar-transitioning/entering/opening/closing/hiding/collapsed`）+ FLIP 动画（`animateSidebarLayout`，4786）+ `transitionend` 监听 + 220ms 兜底计时（`sidebarTransitionTimer`，4891）。→ **延迟补偿**：`transitionend` 与超时双兜底，`finishSidebarTransition`（4814）负责两路收敛与清理。
- 侧边栏宽度：拖拽（5195-5284）永久注册 window mousemove/mouseup，用 `resizing` 标志门控；拖拽中冻结编辑器宿主几何（5236-5252，有注释）。→ **重叠监听**：永久 mousemove/mouseup 与 4.4、设置拖拽的瞬时监听并存。

### 4.4 标签与文档生命周期（批次 3/4）

- `tab.content` **多写者**：`onEditorInput`（2039）、`blur` 回调（1407）、`rebuildEditor`（1649）、`reloadExternalChange`（2696）、`reloadReappearedFile`（2743）、`restoreRecoverySnapshots`（2429）、`preserveUnavailableTab`（2369-2372）、`after()` 归一化（1361-1366）。
- `tab.modified` **多写者**：`onEditorInput`、`performSaveTab`（2264）、`restoreRecoverySnapshots`、`reloadExternalChange`/`reloadReappearedFile`、`keepExternalFileAsUntitled`（2773）、`after()` 归一化。
- `renderTabs`（1945）：整列重建按钮并挂 5 类监听（click/auxclick/pointerdown/pointermove/pointerup）；拖拽重排用模块级 `draggedTabId` 等 5 个变量 + `tabDragGhost` 节点；双 rAF 后 `scrollIntoView`（2026，有注释：等 Vditor `after` 渲染完成）。→ **延迟补偿**。
- `switchTab`（1862）与 `closeTab`（1882）的清理顺序见 §2.2；`closeTab` 是标签级资源清理的唯一收口。
- `pendingEditorContent`：恢复/重建竞态下内容先存内存、`after()` 后写入实例（1357-1360）；`currentContent`（2058）在实例不可用时 **fallback** 到 `tab.content`。

### 4.5 保存与文件安全（批次 4）

- 链路见 §3.1。串行化两层：每标签 `saveOperation` + 每 identity `saveOperationsByIdentity`。
- **fallback**：`rebindDocumentWatches`（452）两次重试后抛 `AggregateError`；`performSaveTab` catch 分支恢复 watch 并提示。
- `saveSettings` 持久化经 `queueSettingsSave`（2100）全局串行；`persistSession`（3923）复用同一队列。

### 4.6 Watcher 与外部变化（批次 4）

- 唯一入口 `handleExternalChange`（4356）：按 `scope`（workspace/document）与 `event` 分派。
- 文档作用域按 `tabFileIdentity(tab) === identity` 匹配（**以 identity 为准**，4395）。
- `watchTabDocument`（425）/`releaseDocumentWatch`（430）/`suspendDocumentWatches`（436）/`rebindDocumentWatches`（452）构成 watcher 所有权管理；`releaseDocumentWatch` 只在无其他标签共享 identity 时真正解绑。
- 工作区作用域删除链路见 §3.4；其余事件经 `treeTimer` 防抖刷新树。

### 4.7 编辑器与 Vditor 生命周期（批次 5）

- 创建：`ensureEditor`（1518）→ `new Vditor(host, editorOptions(tab))`；`editorOptions`（1264）闭包捕获 `tab`，`after`/`input`/`blur`/`upload.handler` 均引用该标签。
- `after()`（1327-1405）：契约校验（`VDITOR.validateHost`，失败置 `editorReady=false` 并报错）→ 资源/大纲 observer 重建 → 锚点导航 → 表格滚动保持 → 内容归一化 → 工具栏挂载与监听（click 捕获 + mousedown 捕获）→ 分栏增强 → 聚焦与滚动恢复。
- 销毁：`rebuildEditor`（1633）与 `closeTab`（1882）各自维护一份清理序列（observer 断开、工具栏归还、`getValue`、`destroy`）→ 两处清理序列需保持一致（**重叠清理路径**）。
- 模式切换延迟补偿：`prepareVditorModeTransition`（1593）= rAF 同步 + 50ms 再同步；`createTab` 的 host 捕获监听对 `[data-mode]` 点击再补一次 50ms 同步（1733-1743）。→ **延迟补偿** × 2，源于 Vditor 内部同步切换模式无回调。
- 滚动恢复：`restoreEditorScroll`（1548）= 3 帧 rAF + 80ms 重试直至稳定（有注释：Vditor 模式渲染晚于 `after`）。→ **延迟补偿**。

### 4.8 分栏视图增强（批次 5）

- 行号：`updateSplitLineNumbers`（1062）触发源 = `lineObserver`（MutationObserver，889）、`lineResizeObserver`（896）、滚动监听、模式切换、全屏、侧边栏完成、输入等十余处，统一经 `scheduleSplitLineNumbers`（866）rAF 合并。→ 有意收敛，但调用点分散是迁移重点。
- 空白符：`renderWhitespaceMarkers`（939）canvas 绘制，`scheduleWhitespaceMarkers`（875）rAF 合并；设置开关 `showWhitespace`。
- 分隔线：`ensureSplitResizer`（1023）拖拽瞬时注册 window mousemove/mouseup（mouseup 自清理）；`splitRatio` 持久化；中点吸附。
- 底部留白：`bottomSpacerObserver`（930）→ `updateEditorBottomSpacer`（917）。
- 清理收口：`disconnectSplitLineNumbers`（902）/`disconnectEditorBottomSpacer`（934），由 `closeTab` 与 `rebuildEditor` 调用。

### 4.9 工作区与文件树（批次 8）

- 链路见 §2.5。树渲染为一次性 DOM 构建 + 逐行监听；刷新整体替换（`refreshTree`，2899），`workspaceRevision` 防过期结果覆盖。
- 重命名/删除流程中的跨域状态（打开标签、最近文件、展开状态、watcher、编辑器 baseDir）联动是批次 8 的主要风险点。

### 4.10 大纲与文档内导航（批次 5）

- 大纲渲染链路见 §2.7；`scheduleOutline` 300ms 防抖（`state.outlineTimer` 为动态字段）。
- 锚点导航 `setupDocumentAnchorNavigation`（3658）：拦截标题锚点与相对 Markdown 链接；修饰键（Ctrl/Cmd）跟随；`hoveredDocumentLink` + keydown/keyup 监听维护光标（5080-5081）；链接提示 `showDocumentLinkTooltip`（611）。
- 查找替换（587-715）：`findMatches`/`findIndex`/`findQuery` 模块级状态；输入 120ms 防抖后定位（`findRefreshTimer`）；widget 焦点用 rAF 回焦（4936-4942）；窗口级捕获 keydown 独立处理 widget 内按键（4943-4966）。→ 与 5100 主 keydown 形成 **重叠监听**（两层都处理 F3/Escape，靠 `findWidgetVisible()` 与事件顺序分工）。

### 4.11 图片与导出（批次 8）

- 见 §2.7。导出正文快照先于对话框获取（防止对话框期间内容变化，有 E2E）。
- `compressImage` 失败 **fallback** 返回原图字节。

### 4.12 设置窗口（批次 8）

- 打开/关闭动画：`openSettings`（3946）双 rAF 加 `modal-open`；`closeSettings`（3972）按 CSS 变量时长 + 30ms 兜底（`settingsCloseTimer`）。
- 拖拽/缩放：`setupSettingsDrag`（4235）注册 window mousemove/mouseup（瞬时自清理）；卡片尺寸持久化 `persistSettingsCardSize`（4224）。
- 分类导航与重置见 §2.6。

### 4.13 菜单与窗口（批次 8）

- `setupAppMenus`（4498）：整菜单树按需重建（每次打开重新生成 popup）；`appMenuCloseHandler`/`appMenuBlurHandler` 注册前先移除旧监听（4500-4501）。
- 主菜单辉光 `updateMainMenuGlow`（151，mousemove passive）。
- `handleMenu`（4457）为菜单动作唯一入口；窗口按钮与标题栏双击见 §2.8。

## 5. 已识别的重构重点（未解释叠加清单）

1. `state.settings` 全字段约 15 个业务写入点（§4.2/§2.6），批次 3 需要给出所有权表。
2. `tab.content`/`tab.modified` 各 6-8 个写入点（§4.4），批次 3/4 需要收敛为文档模型命令。
3. `rebuildEditor` 与 `closeTab` 两份清理序列（§4.7），批次 5 需要统一为 runtime dispose。
4. 三处 50ms/80ms/rAF 模式同步与滚动补偿（§4.7），均源于 Vditor 3.11.3 无公共回调；迁移时保留行为并在 adapter 层集中。
5. 永久 window mousemove/mouseup 对（侧边栏拖拽）与三组瞬时拖拽监听（§4.3/§4.4/§4.12），批次 5/8 需要明确 owner。
6. 两层 keydown 监听对 F3/Escape 的分工（§4.10），批次 5 需要显式化。
7. `syncToolbarWrapHeight` 的多触发源（§4.3），批次 5 收敛为单一布局控制器。
8. `editorTextWidth` CSS 变量两处写入（§4.2）。
9. 三处硬编码中文提示（`请先保存文档，再插入本地图片`、`图片保存失败：`、`已导出 `，行 3717、3737、3896/3911）与 `应用资源加载失败` 致命页（5362）未经过 `locales.js`；0.2.5 保持行为不变，是否本地化留待后续版本决定（记录于此，不在批次 0 修改）。
