## 2. 产品定位与开发边界

Vditor-Electron 的定位是一个本地优先、轻量、专注于打开和编辑普通 Markdown 文件的桌面应用。它基于 Vditor 编辑器引擎，但桌面文件生命周期、标签页、工作区、设置、主题、导出和系统集成由本项目负责。

0.2.0 必须继续遵守以下原则：

- 保持“Markdown 编辑器”定位，不扩展为知识库、数据库式笔记系统或云同步平台。
- 保持普通 `.md` / `.markdown` 文件作为真实数据源，不引入私有文档格式。
- 保持本地优先，不加入账号、遥测、在线服务或必须联网的功能。
- 保留三种 Vditor 编辑模式：所见即所得、即时渲染、分栏预览。
- 保留源码与预览的独立字体、字号、缩放和主题设置。
- 不在 0.2.0 升级 Vditor。继续固定当前 Vditor `3.11.3`，除非现有实现确实因上游缺陷无法完成任务，并在修改前说明理由。
- Vditor 私有 DOM 结构和选择器继续集中在 `src/renderer/vditor-adapter.js`，不得在其他模块随意新增散落的私有选择器。
- 不引入 React、Vue 等 UI 框架，不对渲染层进行一次性推倒重写。
- 不为了“代码看起来现代”而改变已经稳定的用户行为。

### 4.1 0.2.0 实施架构

0.2.0 采用面向本地 Markdown 编辑器的最小充分架构。实现范围以第 2 节的产品定位和本节的组件契约为准。

| 组件               | 技术契约                                                                                                           | 所有权与生命周期                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 安全写入服务       | 接收目标路径和待写入字节，完成同目录临时写入、落盘、替换、权限保留和失败清理；成功后返回可供标签状态使用的预期正文 | main process 单一写入入口；不持有 watcher 或 UI 状态              |
| Recovery Store     | 按标签保存轻量 JSON 快照，启动时校验并提供恢复候选，保存或放弃后清理对应快照                                       | main process 持久化；renderer 只通过恢复流程所需的窄 IPC 使用     |
| File Watch Service | 管理工作区和独立文件监听，等待文件写入稳定后读取磁盘正文并发送规范化文件事件                                       | main process 持有 watcher；标签关闭、另存、工作区切换和退出时清理 |
| 标签文件状态       | 比较磁盘正文、本地正文和 `savedContent`，驱动自动重载、modified 冲突、deleted/reappeared/unreadable 状态与自动保存暂停 | renderer 按标签持有；文件事件是输入，不直接访问文件系统           |
| IPC 边界 helper    | 验证受信任主 frame；高风险 handler 在产生副作用前验证运行时参数                                                    | main process 统一复用；preload 只暴露产品需要的窄方法             |
| 本地资源受控根     | 维护当前工作区根和独立文档目录，规范化并验证本地资源协议请求                                                       | 随文档和工作区打开而注册、关闭而撤销                              |
| 导出服务           | 从一次性内容快照生成可独立打开的 HTML/PDF，转换本地图片来源并隔离 PDF 隐藏窗口                                     | 每次导出独立创建和释放所需资源，不继承主窗口的文件能力            |

实现时优先复用成熟、小型依赖或现有 Electron/Node 能力。若聚焦回归测试证明本节契约无法保证正确性，应先在 Tracker 中记录失败场景、根因和最小修正方案，再调整架构。

# 第一部分：文档保存与异常恢复

## 5. 原子化文档保存

起始基线中的普通文档保存直接写入目标文件。批次 1-7 已改为尽可能安全的替换流程，并补齐正文基线、文件身份、保存队列、watcher reconciliation 和失败收敛；仍需完成跨平台实体机验证，并继续管理已有目标最终复核与替换之间的原子性边界。

本节是 0.2.0 的实施目标；长期有效的文件身份、保存基线、外部冲突、恢复、watcher 和原子性边界统一维护在 [`docs/05-FILE-SAFETY.md`](05-FILE-SAFETY.md)。当本节与长期契约的描述需要区分时，以长期契约和当前代码为准。

要求：

- [x] 在目标文件同目录创建唯一临时文件，避免跨文件系统移动。
- [x] 完整写入、同步并关闭临时文件后再替换目标文件。
- [x] 尽可能保留原文件权限等必要元数据。
- [x] 失败时不得提前删除或截断原文件。
- [x] 失败后清理本次创建的临时文件；清理失败只记录相关路径，不得覆盖原始错误。
- [x] 成功后更新 `savedContent`、修改标记、最近文件和状态提示。
- [x] 保存失败时标签仍保持 modified 状态，并向用户显示可理解原因的错误；当前权限提示按产品约定采用简洁文案，不显示文件名，详见 tracker 中的计划差异记录。
- [x] 自动保存与手动保存统一调用同一安全写入服务。
- [x] 所有文档正文写入只能经过这一安全写入服务；调用方不得各自实现临时文件、替换或权限保留逻辑。服务的文件系统操作应可注入，以便逐阶段制造故障并验证结果。
- [x] 写入前比较待保存字节与当前保存基线；内容确实未变化时不重写磁盘，避免无意义地改变 mtime 或触发 watcher。比较失败时进入正常安全写入，不能把“不确定”当作“相同”。
- [x] 成功保存后记录本次写入的预期正文或字节；watcher 收到事件时读取稳定磁盘内容，并以该内容比较结果判断是否为应用自身保存。
- [x] 明确定义“已提交”的边界：临时文件已完整写入并同步、关闭且成功替换目标。
- [ ] 明确验证 Linux、Windows、macOS 的替换语义，不能假定三个平台的 `rename` 行为完全一致。
- [x] 在 Linux 开发阶段，为替换失败、目标已存在、大小写仅变化的重命名等结果建立可测试的错误/结果模型；Windows/macOS 对文件占用、权限和原生失败语义的实机验证仍见 [`docs/03-CROSS-PLATFORM.md` §9](03-CROSS-PLATFORM.md#9-020-batch-7-deferred-platform-validation)，不将 Linux `rename` 行为编码为通用规则。
- [x] 原子替换产生的目标和临时文件事件必须识别为应用自身保存，不能误报为外部冲突。

必须增加故障测试：

- 写入临时文件失败时原文件内容不变。
- 替换目标失败时原文件仍可读取，标签仍为未保存状态。
- 成功保存后临时文件不存在。
- 保存已有文件时文件权限没有无故变化。
- CRLF/LF 行尾策略继续遵守当前文档状态。
- 待保存内容与磁盘基线相同时不产生替换、mtime 变化或外部冲突事件。
- 应用自身保存事件中的磁盘正文与预期保存正文一致时不触发冲突；时间窗口内出现不同正文时仍必须进入外部变化流程。

## 6. 未保存内容恢复

现有 session 主要保存工作区和已打开文件路径，不能恢复无路径的新文档和已修改但尚未写入磁盘的内容。0.2.0 已增加轻量恢复机制，并由批次 7 补齐 session/recovery 同 identity 的合并和 editor 未 ready 交接。

要求：

- [x] 在应用数据目录中使用独立的 recovery 数据，不把大量正文写进 `config.toml`。
- [x] 为无路径文档和 modified 文档保存恢复快照。
- [x] 快照至少包含稳定 ID、原文件路径（如有）、标题、正文、编码/行尾相关信息、修改时间和当前编辑模式。
- [x] 使用防抖写入，避免每个按键都同步写磁盘。
- [x] recovery 文件本身采用安全写入。
- [x] recovery 格式包含简单 schema 版本，并对必要字段和单快照大小做运行时校验；损坏、超限或未知版本的快照不得使应用启动失败。
- [x] 无法解析的快照记录不含正文的诊断信息并跳过；错误提示和日志不得泄露完整正文。
- [x] recovery 目录视为应用私有数据，不加入本地资源协议受控根；renderer 只通过恢复候选、恢复和放弃所需的窄 IPC 使用该数据；在平台支持时使用仅当前用户可读写的权限。
- [x] 文档成功保存且内容与磁盘一致后删除对应快照。
- [x] 用户主动“不保存”关闭文档后删除对应快照。
- [x] 正常退出且所有文档已妥善处理后清理无用快照。
- [x] 异常退出后再次启动，直接打开可恢复内容，并以文档级警示横幅提供保存、另存为或放弃恢复操作。
- [x] 恢复不能静默覆盖磁盘上更新的文件；原文件未变化时可保存此版本，磁盘版本已变化或原文件不可用时保留恢复内容但仅允许另存为。
- [x] 恢复无路径文档时继续作为 Untitled 文档打开，不擅自创建磁盘文件。

验收标准：

- 新建未命名文档并输入内容，模拟异常终止后可以恢复。
- 修改已有文档但未保存，模拟异常终止后可以恢复。
- 正常保存后不再重复提示旧快照。
- 用户明确放弃恢复后，下一次启动不再提示同一快照。
- 构造损坏、超限和未知 schema 快照时应用仍能启动，并只处理可验证的快照。

# 第二部分：外部文件变化与工作区一致性

## 7. 打开文件的监控范围

当前监控主要依赖工作区 watcher，独立打开且位于工作区之外的文件也必须被监控。

当前基线：工作区 watcher 报告目录结构，打开文档拥有独立的内容 watcher；稳定正文、预期保存正文和独立文件状态由 renderer 决策。应用自身保存使用短时抑制配合正文比较，不能仅依赖时间窗口。

要求：

- [x] 工作区 watcher 仅处理目录结构事件；每个已打开文档使用独立内容 watcher，避免同一内容事件重复监听或重建文件树。
- [x] 工作区之外的已打开文件建立必要的文件或父目录监听。
- [x] 标签关闭、文件另存、工作区切换和应用退出时正确释放监听资源。
- [x] 同一文件被多个入口打开时不创建重复 watcher。
- [x] 应用自身保存引发的文件变化不能被误报为外部冲突。
- [x] 不再把固定 1.5 秒 `ignoredChanges` 时间窗作为唯一判断。可保留短时去抖，但任何事件最终以稳定读取到的磁盘正文与当前标签正文/保存基线比较为准。
- [x] 在 Linux 和可注入路径模型中规范化文件身份，并覆盖大小写敏感、符号链接和同一文件不同路径表示；Windows/macOS 实际卷语义仍见 [`docs/03-CROSS-PLATFORM.md` §9](03-CROSS-PLATFORM.md#9-020-batch-7-deferred-platform-validation)。
- [x] 文件身份比较统一经过 `src/main/services/file-identity.ts`，覆盖 Linux 本地路径、Windows 盘符输入和缺失祖先路径的可测试模型；大小写不敏感卷、Unicode 规范化及 junction/Finder alias 仍待实体机验证。
- [x] 正确合并编辑器、资源管理器和同步软件可能产生的短时间连续 `add` / `change` / `unlink` 事件，避免重复横幅或错误自动重载。
- [x] 文件内容 watcher 使用 chokidar `awaitWriteFinish` 或等价的稳定等待；目录树 watcher 不因读取正文的稳定等待而无故延迟节点显示。
- [x] 每个 watcher 都有明确的 disposed/cleanup 状态；关闭、另存、重绑或切换工作区后，已开始但尚未完成的异步读取不得再更新标签状态。
- [x] mtime、大小等元数据只用于减少不必要读取，不能作为内容相同的最终依据；磁盘正文相同时忽略事件，正文不同时进入自动重载或冲突流程。
- [x] watcher 以规范路径标识监听目标，并在回调和异步读取完成时检查当前绑定及 disposed 状态；已失效的结果直接丢弃。

批次 3-5 已完成的文件状态边界：

- [x] 外部删除或权限不可读进入独立持久状态，暂停自动保存并保留内存正文；不会静默重建原文件。
- [x] 文件重新出现时不自动替换内存正文，并额外发送工作区结构事件刷新 sidebar。
- [x] 删除状态下明确确认重建后，复制首次进入不可访问状态时冻结的正文；自动保存开启时取当刻编辑器正文，关闭时取最后一次成功保存的正文。
- [x] 重建成功显示 5 秒非驻留通知；复制失败不回滚已完成的重建。

## 8. 外部修改冲突状态

当磁盘文件变化且当前标签存在未保存内容时，不能只显示会自动消失的状态栏消息，也不能允许自动保存随后覆盖外部内容。

当前基线：冲突标签已有持续可见的 `!` 标记；活动标签在编辑区顶部显示不抢焦点的持久横幅；可选择“忽略当前标签修改并重载”或“忽略外部更改”；冲突未处理及忽略外部更改后会暂停自动保存；无本地修改的已有文件继续自动重载。sidebar 新建或重命名不会被 Untitled 标签阻止，而是由同一路径映射进入该冲突流程。

批次 4-5 已完成文件级 modified/deleted/reappeared/unreadable 决策流程：稳定磁盘正文快照驱动重载，modified 横幅提供重载、另存当前内容、忽略外部更改和明确覆盖；deleted/unreadable 横幅暂停自动保存并提供与状态匹配的保护动作；reappeared 不静默覆盖内存。忽略后的保存仍需二次确认，重复外部变化会使旧覆盖确认失效。持久横幅统一使用 `assets/notification/warning.svg`；重建成功通知使用蓝色 `assets/notification/notification.svg` 和 5 秒计时。目录级路径状态由批次 6 完成，批次 7 又补齐了保存/恢复/watcher 的组合竞态保护。

### 8.1 文档级持久提示

将当前外部修改横幅的定位、宽度、主题色、图标/状态色、文案和动作布局抽取为可复用的**文档级持久提示**视觉原语，例如 `document-notice`。它仅服务于当前活动标签的、需要用户明确处置的文档状态，固定在编辑区顶部且不抢占编辑焦点。

不得将其实现为任意模块可随意调用的全局通知通道：具体提示的可见性、自动保存暂停、按钮动作和清理时机必须继续由文件/标签领域状态驱动。短暂成功消息与普通错误仍使用现有状态栏消息，不与持久提示混用。

`modified`、`deleted`、权限不可读等状态可以复用该外观，但各自必须拥有独立的文案、动作集合和状态转换，不能只更换一行提示文字。

### 8.2 对话框卡片与受限拖动

`document-notice` 不与确认对话框合并为同一种 UI 组件：前者是编辑区内、不抢焦点的文档状态提示，后者是带遮罩、焦点和明确操作结果的模态决策界面。两者可以共享颜色、边框、圆角、阴影、标题/动作间距等设计 token，但不得共享可见性、状态转换或动作分发逻辑。

将对话框的共享外观和可选交互收敛为 `dialog-card` 约定：确认框、未保存变更框和未来的应用内决策框复用 card/header/content/footer 结构；各对话框仍各自拥有 Promise resolver、焦点策略、Escape 行为和按钮语义。不要将其扩展为任意模块可调用的全局 modal 服务。

当前未保存变更框已支持在窗口范围内拖动、关闭后恢复居中且不可调整尺寸；设置框另有尺寸调整与持久化需求。0.2.0/后续 renderer 拆分时，应将两者重复的边界计算抽为小型受限拖动 helper，例如 `setupBoundedCardDrag({ card, container, handle, enabled })`：

- [ ] helper 只处理指针拖动、窗口边界收敛、窗口 resize 后重新收敛和 listener cleanup；不处理尺寸调整、位置持久化、焦点或业务动作。
- [ ] 拖动是否启用必须由具体对话框声明；设置框、未保存变更框和普通确认框不得因复用 helper 而获得相同的尺寸调整或持久化语义。
- [ ] 为可拖动对话框测试标题栏拖动、窗口边界、关闭后位置复位和“尺寸不变”；为不可拖动对话框测试其默认居中与不可拖动状态。
- [ ] 只有出现第三类具有相同模态语义的可拖动卡片时，再评估是否将 `dialog-card` 升级为独立 DOM/controller 模块；在此之前保持轻量 helper，避免形成新的全局 UI 框架。

引入持久的冲突状态，例如：

```ts
type ExternalConflict = null | {
  kind: 'modified';
  detectedAt: number;
  diskMtime?: number;
};
```

后续补完：

# 第三部分：Electron 安全边界

## 10. 安全原则

Vditor-Electron 会打开用户提供的 Markdown，其中可能包含 HTML、链接和远程资源。渲染器同时能够通过 preload 调用本地文件功能，因此 0.2.0 必须缩小“渲染内容 → Electron 权限 → 本地文件系统”的组合风险。

安全加固不能只修改一个开关，必须按入口逐项检查。

## 11. 导航与外部链接

- [x] 为 `window.open`、`will-navigate` 和 preload 暴露的 `openExternal` 使用同一套 URL 校验函数。
- [x] 只允许明确支持的 `https:`、`http:` 和必要的 `mailto:`。
- [x] 拒绝 `file:`、`javascript:`、`data:`、自定义应用协议和无法解析的 URL。
- [x] 不允许 Markdown 中的链接触发应用内部导航到任意网页。
- [x] 为 URL 校验函数增加单元测试，包括大小写、空白、编码和恶意 scheme 边界情况。

## 12. IPC 调用方校验与参数校验

- [x] 为所有具有文件、窗口、导出、设置和外部链接权限的 IPC handler 校验 `event.senderFrame` / 来源 URL。
- [x] 只接受来自本应用受信任 renderer 页面的调用。
- [x] 抽取一个小型受信任主 frame 校验 helper，由所有特权 handler 复用。
- [x] 来源校验使用解析后的精确应用 origin、页面路径和主 frame 身份，不使用 `startsWith`、模糊 host 匹配或仅检查 `event.sender` 是否存在。
- [x] 对文件写入、删除、重命名、目录创建、导出和外部链接等高风险入口的路径、枚举、数字范围和对象结构进行运行时校验，不能只依赖 TypeScript 类型。
- [x] 先完成来源和参数校验，再访问文件系统、显示系统对话框或执行其他副作用。
- [x] preload 不暴露底层 `ipcRenderer`，继续保持窄 API。
- [x] 对删除、重命名、创建目录、写文件等高风险操作采用明确参数结构并返回可处理的错误。
- [x] 对 renderer 返回稳定、可本地化且不泄露绝对敏感路径或内部堆栈的领域错误；详细诊断只进入受控主进程日志。
- [x] 把 IPC channel、输入和返回结构集中定义，避免 main、preload、renderer 三处漂移。
- [x] 创建和重命名项目时，将平台不接受的名称、权限/占用和已存在等失败转换为可本地化的领域错误；不得把 Linux 上可创建的文件名视为所有平台都可接受。

## 13. 本地资源协议与文件能力范围

当前本地图片协议不能继续把任意绝对路径视为可读取资源。

> **2026-08-31 实施检查点：** Linux 代码、聚焦单元测试和资源/IPC Electron 专项已完成；SVG 当前按明确兼容限制拒绝。`check:all`、用户手测以及 Windows/macOS 实机验证仍未在本检查点关闭。

目标行为：

- [x] 仅允许读取当前已打开文档、其授权资源目录或已打开工作区范围内的资源。
- [x] 本地资源协议维护受控根目录集合：当前工作区根，以及工作区外已打开文档各自的目录。普通打开、保存、重命名和删除继续使用各自的窄 IPC 与参数校验。
- [x] 先拒绝无效百分号编码、NUL、反斜杠混淆、绝对路径注入和 `..`，再把 URL 路径转换为本地路径并通过规范化、realpath 和路径边界确认其位于受控根内。
- [x] 目录包含关系使用路径边界和规范化后的比较，不使用简单字符串前缀；比较规则必须考虑 Windows 盘符与大小写不敏感文件系统。
- [x] TOML 配置、Chromium user data 和 recovery 目录不得被注册为资源根；协议仅响应已授权的编辑器本地资源请求。
- [x] 不允许通过协议探测任意系统文件是否存在；对未授权与不存在目标返回外部不可区分的中性失败，内部日志只保留拒绝分类，不记录 URL、真实路径或正文。
- [x] 文档关闭或工作区关闭后撤销不再需要的访问能力。
- [x] 继续支持 Markdown 相对图片、粘贴图片目录和现有本地预览。
- [x] 路径授权通过后仍按资源类型决定响应：仅内联当前预览实际需要的图片类型，设置准确的 `Content-Type`、`X-Content-Type-Options: nosniff` 和 `Cache-Control: no-store`；HTML、JavaScript、XML 和未知类型不得作为可执行内容内联。
- [x] SVG 当前明确拒绝；待未来允许时，必须先以准确 MIME 和真实 Electron 测试证明其作为图片不会执行脚本或导航。
- [x] 为合法路径、越界路径、编码绕过、反斜杠、符号链接/ junction 等价 canonical 越界、不存在路径、私有目录和文档/工作区关闭后的授权撤销增加测试；实体 Windows junction 状态仍如实记录。

根目录在打开/关闭文档和工作区时增删；扩展名和 MIME 只决定已授权资源如何响应，不能替代路径授权。

## 14. Renderer sandbox、CSP 与 HTML 清理

- [x] 在测试现有 Vditor、preload 和本地协议兼容性的前提下，尝试启用 BrowserWindow renderer sandbox；当前 CommonJS preload 的本地 `ipc-contract` import 在 sandbox 中无法加载，真实 Electron 会停在 renderer ready 前。保留 `sandbox: false`，并将 bundled-preload 迁移列为单独工作。

## 15. macOS 窗口关闭确认状态

批次 12 已将关闭确认绑定到具体 `BrowserWindow`。此前进程级状态会让一次确认关闭在 macOS `activate` 重建窗口后仍然有效，从而让新窗口的未保存文档绕过确认；macOS 实机验证仍递延。

要求：

- [x] 每次创建新 BrowserWindow 时重新初始化关闭确认状态，或改为按窗口保存状态。
- [x] 一个窗口的确认不能影响以后创建的窗口。
- [x] 正常关闭、取消关闭、保存后关闭和“不保存”关闭均保持正确行为。
- [x] 增加可在非 macOS 环境执行的状态单元测试；macOS 集成验证递延到有实体机条件时执行。

## 16. 设置保存不应无条件重建全部编辑器

展示、布局和应用级设置会直接更新已打开的编辑器；只有 Vditor 初始化后没有安全公开 setter 的选项才会重建。Vditor 内部撤销栈和选区不能通用恢复，因此重建范围必须保持最小。

要求：

- [x] 对设置进行分类：可热更新、只影响布局/展示、确实需要重建编辑器。

- [x] 只有 Vditor 初始化后无法安全改变的选项才触发重建。
- [x] 如必须重建，保留内容、模式和滚动位置；Vditor 3.11.3 没有通用选区/撤销栈恢复 API，此限制已明确记录。
- [x] 增加真实 Electron 测试确认只修改外观或工具栏显示后，用户仍可撤销之前的编辑。

## 17. HTML/PDF 导出中的本地图片来源

## 20. 自动化测试要求

### 20.1 单元测试

至少覆盖：

- `sanitize` 默认清理恶意 HTML、关闭前的本地化风险确认，以及关闭后 CSP 对内联事件处理器的拦截。

至少覆盖：

- 设置外观和工具栏显示后撤销历史仍可使用。
- 外部修改冲突时自动保存被暂停。
- 外部修改冲突横幅的重载、另存、忽略后确认覆盖和显式覆盖动作，以及重复磁盘变化使旧确认失效。
- 外部删除后不会静默重新创建文件；重新出现不会静默覆盖内存正文；不可读状态会暂停自动保存。
- 重建前正文备份到系统剪贴板，自动保存开启/关闭分别冻结正确的正文基线，复制成功显示 5 秒通知，复制失败不回滚重建。
- 异常退出后的未命名文档恢复。
- watcher 在另存、标签关闭和工作区切换后的迟到读取不会污染新状态。
- 本地资源协议无法通过编码或符号链接越界，允许的资源类型不能取得脚本执行或应用导航能力。
- Security 设置卡片只有开关可改变 `sanitize`；风险确认复用可拖拽的通用对话框，内容与图标不可选中。
- PDF 导出窗口保持隔离，HTML/PDF 结果不包含应用内部协议。

E2E 测试必须等待明确的 UI 状态或数据状态，不使用大段固定 sleep 掩盖竞态。
